「Bash は最後の手段」と CLAUDE.md に書いても守られない — 警告フックで7日数えたら grep 286回・ls／find 64回。数えてから拒否に格上げし、先頭の語だけで判定して # tool-exception: の逃げ道を残す

— 昨日の「指摘は再現してから直す」の運用版。ルールは書く前に「どれだけ破られているか」を測る。

あいやま氏（9/24）。CLAUDE.md の「ファイル検索は専用ツールを使ってください。Bashは最後の手段です」は守られず、警告だけ出すフックで7日数えると grep 始まりが 286回、ls／find 始まりが 64回の計350回。拒否に格上げした。判定は先頭のコマンド語だけなので git log | grep foo は通り、tail -f は Read で代替できないので通し、# tool-exception: <理由> を付けた命令は無条件で通す。含意: 拒否は「放置すると壊れるもの」、警告は「直せば済むもの」に分ける。

試すなら: .claude/settings.json の hooks.PreToolUse に "matcher": "Bash" でスクリプトを登録 → 最初は数えるだけ（exit 0 で通し、先頭の語をファイルに追記）→ 7日分を見て拒否対象を決め、止めるものは exit 2（stderr が Claude に返る）か {"hookSpecificOutput":{"permissionDecision":"deny","permissionDecisionReason":"…"}} を stdout に返す（exit code と JSON の仕様は docs/en/hooks で確認済み。記事はフックの種類を明示していない）。

出典: Zenn — CLAUDE.mdに書いても守られなかったので、7日ぶん数えてからフックで拒否しました

特集: 実装は並列、マージは直列 — サブエージェントと並列セッションの「分担設計」を4つの原則で組む

worktree の隔離（9/20 特集①）だけでは衝突も同調も消えない。①縄張りを物理的に切る — orca_forge氏（9/15）は3〜5セッションを worktree と担当領域で分け、着手前に範囲を宣言、完了時に基点と触った箇所を報告させて「ファイル競合がほぼ消えた」。②共有ファイルは先に片付け、マージは直列 — Quintet Kit氏（9/18）の衝突源はルーティング定義や package.json など「一覧構造」5種。一覧を持たない構造にするか、共有ファイルの作業を先に1つ通す。

③サブには目的と出力先だけ渡し、返すのは JSON だけ — Kaito Narimoto氏（9/24）はログ調査の要約とレビューをサブに出し、渡すのは目的と保存先パスだけ、所見はファイルに書かせてパスだけ受け取る。サブは会話履歴を見ない。渡さない設計が親の文脈を守る。④検証役を同調させない — マルチンゲール氏（9/20）の Dynamic Workflow は指摘9件を全部「再現できた」と通した。同じモデルが同じ文脈を読めば実質1票。実ファイルとテスト結果だけを根拠に反証で問い、最上位モデルを検証に置くと 6採用・1棄却・2未確認、736K→420K トークンに。

写す形（.claude/agents/）: 実装役は isolation: worktree／model: sonnet、本文は「依頼の範囲だけ実装、範囲外は止めて報告、一覧ファイルは差分案だけ」。検証役は tools: Read, Grep, Bash／model: opus／omitClaudeMd: true、本文は「誤りを示せ。根拠はテストの結果だけ、迷えば refuted=true。返答は {"refuted":…,"evidence":"…"} の1行」。やらないこと: 同じモデル・同じ入力の検証役を並べる、一覧ファイルを並列で触らせる、司令塔役の常駐（9/25 GENDA）。

試すなら: .claude/agents/implementer.md と refuter.md を上の frontmatter で作る → 依頼文に「触ってよいパス／触らないパス」と「共有の一覧ファイルは差分案だけ」を書いて implementer を2つ並列に → 戻った差分を1つずつマージ → refuter に「この変更が誤りであることを示せ」で検証させ、evidence にコマンドと結果が無い判定は採用しない（frontmatter のキー名は docs/en/sub-agents の一覧で確認済み。isolation: worktree の挙動は 9/20 特集①）。
