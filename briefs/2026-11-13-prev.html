— 1M 文脈のモデルは 97 万トークンまで compact が動かない。設定 1 行で早めた記事と、サブエージェント定義で同じことをする公式 docs の項目を合わせて読む。

筆者 1 人の記録で設定前 15 日と設定後 11 日を比較。~/.claude/settings.json に "autoCompactWindow": 500000 を書き、97 万トークンまで育ってから動いていた自動 compact を 50 万で動かす。1 回の送信トークン平均は 43.2 万→26.3 万（39% 減）、1 日分の API 定価換算は $483→$336（30% 減）。代わりに compact は 1 日 3.7 回→15.3 回。離席対策（50 分空いて 20 万以上なら compact、60 分で新しい会話）も同時に入れ、1 時間以上空けて戻った回の書き直しは 1 日 $43.6→$17.3。

公式 docs でも autoCompactWindow は settings の正式なキーで、環境変数 CLAUDE_CODE_AUTO_COMPACT_WINDOW が優先。サブエージェント単位なら定義の frontmatter に autoCompactWindow: 200000（v2.1.296 以降。200k は 200 と読まれて無効）。限界は n=1 で期間も仕事も違うこと、金額が定価換算の概算なこと、離席対策と同時に入れたので効果を分けられないこと。

試すなら: ~/.claude/settings.json に "autoCompactWindow": 500000 を足す（環境変数 CLAUDE_CODE_AUTO_COMPACT_WINDOW を設定していると無視されるので先に外す）→ 1 週間、1 回あたりの送信トークンと compact の回数を前後で比べる → 長いログを読む専用サブエージェントだけ早めるなら .claude/agents/log-reader.md の frontmatter に autoCompactWindow: 200000（整数で。claude --debug のログに invalid autoCompactWindow が出たら値が無効）。

LM Studio の 10.21 tok/s が、同梱の llama-server を直接起動して --n-cpu-moe 32 にすると 30.66 tok/s。RTX 3060 Ti 8GB・Qwen3.6-35B-A3B Q4_K_M（mukai3 氏 11/11）

— MoE のエキスパートを CPU に置く層数で 3 倍の差。12〜16GB なら層数をさらに減らせるので、同じ手順で自分の最適値を探す価値がある。

RTX 3060 Ti 8GB で、LM Studio 同梱の llama-server.exe を直接起動し、Qwen3.6-35B-A3B-UD-Q4_K_M で測定。LM Studio 既定（エキスパート全部 CPU）10.21 tok/s、--cpu-moe 25.87、--n-cpu-moe 32 30.66（VRAM 増分 6,565MiB）、Ollama 0.34.3 は 27.71。--n-cpu-moe 30 は共有 GPU メモリに溢れて 17〜18 に落ちた。各設定 4 回・512 トークン。31・33 と長文脈は未測定。

試すなら: ./llama-server -m ＜Qwen3.6-35B-A3B-UD-Q4_K_M.gguf＞ -c 32768 -np 1 -ngl 99 --n-cpu-moe 32 --host 127.0.0.1 --port 8091（記事は ~/.lmstudio/extensions/backends/ 配下の LM Studio 同梱 llama-server.exe を使用）→ 12〜16GB なら --n-cpu-moe を 32 から 2 ずつ下げ、tok/s と共有 GPU メモリを毎回記録 → 共有メモリが増えた段階の 1 つ手前が自分の最適値。各設定は初回を捨てて 3 回平均。
