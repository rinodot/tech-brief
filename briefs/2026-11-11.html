Claude Code の git push を PreToolUse hook で止めて Codex にレビューさせた 2 か月の実測。960 push 中 Codex が判定を返した 428 回のうち 253 回（約 59%）を block、判定まで中央値 105 秒。block 142 件の決着は「Claude が直して Codex 通過」44%、「直して人間が解除」18%、「直さず人間が解除」30%、Codex 停止で素通り 6%（shoma46 氏 11/10）

— 書いたモデルと別のモデルに push 前の差分を見せ、deny で Claude を修正に戻す型。hook 1 本と最小版約 35 行のスクリプトで組める。

shoma46 氏（11/10）。PreToolUse hook で git push を捕まえ、git merge-base HEAD origin/main からの差分を codex exec --sandbox read-only に渡し、致命的・重要な指摘があれば deny で止める。8/9〜10/7 の 960 push のうち Codex が判定を返したのは 428 回（10 行未満は呼ばない、エラーは分母から除外）、block は 253 回（約 59%）、判定までの中央値は 105 秒。

同じブランチで続いた block をまとめた 142 件の決着は、Claude が修正 commit を積んで Codex 通過 62 件（44%）、修正後に人間が解除 25 件（18%）、修正せず人間が解除 42 件（30%）、Codex のエラー・タイムアウトで未レビュー通過 8 件（6%）、以後 push なし 5 件（4%）。Codex が落ちたら || exit 0 で通す fail-open、ChatGPT Plus の上限で動かなかったことが 46 回以上。含意: 止めるのは別モデル、解除は人間。「直さず解除 30%」は誤検知の目安。

試すなら: ~/.claude/settings.json の hooks に "PreToolUse":[{"matcher":"Bash","hooks":[{"type":"command","command":"~/.claude/hooks/pre-push-review.sh","timeout":660}]}] → スクリプトは stdin の tool_input.command に git push が無ければ exit 0、あれば base=$(git merge-base HEAD origin/main) の git diff ${base}...HEAD を codex exec --cd "$repo" --sandbox read-only --output-schema ~/.claude/hooks/review-schema.json --output-last-message "$result" に渡し、致命的・重要なら permissionDecision を deny（理由付き）で返す JSON を出力（記事に最小版約 35 行と schema）→ コミット本文の # claude-review-skip: ＜理由＞ は ask に落とす → 小差分を飛ばすなら「レビュー済み HEAD」を進めず次回の範囲に含める → Codex が無ければ同じ型で claude -p に差分を渡せるが、同じモデルのレビューの甘さは著者も限界に挙げている。

試すなら: Google Cloud の請求レポートを SKU 別に切り替えて Firestore の読み取りの行を見る → Firebase コンソールの Firestore「使用状況」で 1 日の読み取りが 5 万回を超える日を数える → 定期関数は取り込み結果の crypto.createHash("sha1").update(JSON.stringify(rows)).digest("hex") を保存し、前回と同じなら continue（書き込みも読み直しも飛ばす）→ 集計は functions.firestore の書き込みトリガーで変わった 1 件だけ → 定期関数は cronEvery5Minutes のような 3 本に集約し、中の各ジョブは Promise.allSettled → CLAUDE.md に「新しい定期処理は関数を増やさず、この 3 本のどれかに足す」→ Hosting の古いリリースも削除（著者の環境は 10GB 近く）。
