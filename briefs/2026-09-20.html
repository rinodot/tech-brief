claude.ai で有効にした Skills が、ターミナルの Claude Code にも降りてくるようになった（v2.1.275）— ~/.claude/skills/synced/ に約10分ごと同期。同じリリースで ctrl+enter の「今すぐ送る」と /plugin install --marketplace

— Cowork と CLI で同じ Skill を二重管理しなくてよくなる。代わりに「どちらを正にするか」を決める必要が出る。

9/17 の v2.1.275 から、claude.ai アカウントでサインインしたターミナルには、そのアカウントで有効な Skills（自作や組み込みを含む）が起動時に ~/.claude/skills/synced/ へ降り、約10分ごとに同期される。/skills と /context では「claude.ai sync」の枠に出て、/名前 か /anthropic-skills:名前 で呼ぶ。ローカルに同名があればそちらが /名前 を取る。同期フォルダの直接編集はアカウントに戻らない。止めるなら user settings に "syncClaudeAiSkills": false。

同じリリースで、ctrl+enter（または ctrl+x ctrl+s）で今のターンを中断してキュー済みメッセージを一括送信、/plugin install <plugin> --marketplace <source> は未登録のマーケットプレイスを追加してから入れる。含意: Skills の置き場が「アカウント」と「リポジトリ」の二層になる。端末を跨ぐ汎用の手順はアカウント側、プロジェクト固有は .claude/skills に置き、同名を避ける。

試すなら: claude update → /skills で「claude.ai sync」の枠を見る → claude.ai の設定 → Skills で1つ有効にし、10分後に /context に増えるか確認 → 要らなければ ~/.claude/settings.json に "syncClaudeAiSkills": false（プラグインは syncClaudeAiPlugins。docs/en/skills で確認済み、docs は v2.1.273 以降と記載）。

出典: GitHub — anthropics/claude-code Releases v2.1.275

Firebase AI Logic の generateContent を、Cloud Functions で「Gemini に送る前」「アプリに返す前」に検査・書き換え・拒否できるようになった（プレビュー、9/10）

— アプリを配り直さずに、プロンプト検査・出力トークンの上限・ユーザー別のログをサーバー側へ寄せられる。

firebase-functions/v2/ai の beforeGenerateContent／afterGenerateContent をデプロイすると、AI Logic を通る generateContent ごとに呼ばれる。前段で HttpsError を投げれば Gemini に送られず、書き換えた request を返せば差し替え。イベントの authId でユーザー別の制限も書ける。制約: 各1本／プロジェクト、ストリーミングは対象外、Blaze 必須。含意: ガードレールの更新をアプリの審査待ちから切り離せる。

試すなら: functions/ で npm i firebase-functions@latest → index.ts に export const guard = beforeGenerateContent((event) => { if (event.data.api !== geminiV1Beta) return; /* 検査 */ }); → firebase deploy --only functions → firebase functions:list に載るか確認。関数の分だけ応答が遅くなるので実機で計る。

出典: Firebase Docs — Run scripts before and after requests to Gemini（Firebase AI Logic）

特集: サブエージェントを worktree に隔離して並列に走らせる — .claude/agents/ の1ファイルから、片付けまで

git worktree（履歴を共有する別の作業ディレクトリ＋ブランチ）をサブエージェント単位で持たせる手順。

①下ごしらえ: .gitignore に .claude/worktrees/ を足す。.env を新しい worktree にも複製するなら、プロジェクト直下の .worktreeinclude に .env と書く（gitignore 済みのものだけ複製）。②定義: .claude/agents/refactorer.md の frontmatter に name・description・isolation: worktree、本文は「直したらテストを回して報告」。毎回自分の worktree で動き、本体への Edit／Write や git -C はツールエラーになる。③分岐元: 既定はリモートの既定ブランチ。未 push の作業から切るなら .claude/settings.json に {"worktree": {"baseRef": "head"}}。④走らせる: 「refactorer で A と B を並列に」と頼む（定義なしでも「use worktrees for your agents」で同じ隔離）。走行中は git worktree lock が掛かる。⑤片付け: 変更がなければ自動削除。あれば残るので git worktree list で枝を確かめ、git diff main...<枝> を見てマージし、git worktree remove <パス>。放置分は cleanupPeriodDays 後の定期掃除が消すが、未コミット・未 push の作業があれば残る。

注意は hooks。${CLAUDE_PROJECT_DIR} は元のプロジェクト直下のままで、worktree の場所は hook 入力 JSON の cwd に入る。含意: 並列化の単位を「ターミナル」から「エージェント」に下げられる。共有ファイルを同時に触る分け方では衝突は消えない — 実装は並列、統合は逐次。

試すなら: echo '.claude/worktrees/' >> .gitignore && printf '.env\n' > .worktreeinclude → .claude/agents/refactorer.md に上の frontmatter → claude で「refactorer を2つ並列で、A は…、B は…」→ 終わったら git worktree list（コマンドと設定キーは docs/en/worktrees と docs/en/sub-agents で確認済み）。

出典: Claude Code Docs — Run parallel sessions with worktrees ／ Claude Code Docs — Subagents（supported frontmatter fields）
