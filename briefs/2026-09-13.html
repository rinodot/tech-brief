同じ Qwen3.8-27B でも Q4 と Q5 でコード生成の正答率が 64.5%→74.8% — 1,692回の実測で「4bit は速いが、MBPP で10ポイント落ちる」

— 16GB に載る Q4 を選ぶ前に、何を捨てているかが数字で分かる。

toyoshi氏が9/11に公開。Tesla V100（32GB）で Qwen3.8-27B の3量子化（UD-Q4_K_M 15.33GiB／UD-Q5_K_M 18.41GiB／UD-Q6_K 20.47GiB）を、HumanEval 164問と MBPP 400問・温度0の pass@1 で比較（計1,692回）。MBPP は 64.5%→74.8%→77.2% と単調に上がり、HumanEval は 93.9／93.3／93.3% で差が出ない。生成速度は 32.31→28.13→25.79 tok/s。

著者の結論は「Q4→Q5 の10.3ポイントは 3GiB と13%の速度低下に見合う。Q5→Q6 の2.4ポイントは微妙」。注意: 32K コンテキストの f16 KV 込みだと Q4 でも 17.85GiB を使うので、16GB では KV を q8_0 にするかコンテキストを削る。HumanEval は天井に張り付いて差が出ないので、量子化の比較は MBPP 側で見る。含意: ローカルでコードを書かせるなら「載る最小の量子化」でなく「Q5 が載る構成」から考える。

試すなら: llama-server -m Qwen3.8-27B-UD-Q5_K_M.gguf -ngl 99 -fa on -c 32768 -ctk q8_0 -ctv q8_0 で立て、自分の言語の小問20題を温度0で Q4 と Q5 に解かせて差を見る。速度より先に「落とす問題の数」を数える。

出典: Zenn — 量子化はコードの正しさを変えるか: V100で1,692問を実行して測った

claude --worktree は「変更なしで終了」すると作業ツリーごと消える — 残したいなら名前付きセッションにするか、SessionStart で git worktree lock を掛ける

— 依存を入れ終えた worktree を次回も使い回すための数行。

公式仕様では、名前なしセッションは終了時に worktree がクリーンだとディレクトリとブランチを自動削除し、名前付きなら残すか聞かれる。daydreamer氏（9/12、v2.1.263）は自分で git worktree lock --reason を掛けると消えないことを確認し、SessionStart フックで unlock→lock を自動化した。公式にも「自分で掛けたロックは掃除で解除されない」とある。含意: 使い回すなら、まず名前を付ける。

試すなら: claude --worktree feat -n feat で始めれば終了時に残すか聞かれる。常に残すなら記事の pin-worktree.sh を .claude/hooks/ に置き、.claude/settings.json の SessionStart に登録（著者の環境では settings.local.json では効かなかった）。片付けは git worktree unlock → git worktree remove。

出典: Zenn — Claude Code の --worktree が終了時に消える問題を git worktree lock で防ぐ

特集: Claude Code の費用を3つの実ログで分解する — 起動の固定費・1往復の変動費・伸びるほど増える再読費

費用は「トークン数」で来るが、手を打てる単位は3つ。起動のたびに乗る固定費、1往復ごとの変動費、会話が伸びるほど膨らむ再読費。3人の実ログをこの順に並べる（キャッシュの原理は9/6特集）。

①固定費 — activecore の Sei氏（9/2）は転写の最初の応答の usage を足し、何もしないうちに 71,657 トークンが乗っていると測った。うち設定側が 32,096（45%）で、Skill 一覧 7,936、MEMORY.md 6,502、CLAUDE.local.md 3,769、起動フック 3,028＋1,264、出力スタイル 2,719、グローバル CLAUDE.md 2,590、ツール定義 2,024、エージェント一覧 1,118。ルール10本を常駐から外して −9,057、CLAUDE.md の書き直しで −5,230、2週間で 43,814→32,096。

②変動費 — Shinn_Matsumoto氏（9/10）は30日・132.7億トークン（97.5%がキャッシュ読み）から、費用の単位は時間でなく往復回数だと結論した（5.74回/分、見積もり誤差 3.3倍→2.6倍）。1ターン $0.08 に対しサブエージェント1本 $2.07。「走行コストより帰還コスト。報告が親に丸ごと乗る」ので1回4本まで、安全係数は P90 の1.24倍。

③再読費 — hitokraft氏（9/8）の48時間・12,898ターン・40億トークンは 77.5% がキャッシュ読み、出力は 9.3%。最大の1セッション（36.4時間・2,441ターン・平均 509K）だけで全体の3割、同じ1ターンが会話の長さで5倍以上変わる。固定費 45K も全ターンに乗って 14.5%。約200K／300ターンで切る試算は 3,487M→643M。

含意: 費用 ≒（固定費＋会話）×ターン数。効く順は、セッションを切る→固定費を削る→ターン数（帰還）を減らす。

試すなら: 起動直後に /context で設定側の内訳を見る（目安: 50K 超なら Skill 一覧と CLAUDE.md から削る）。npx ccusage@latest session でセッション別のキャッシュ読み比率を並べ、300ターンを超えるものは /clear で切る。転写 ~/.claude/projects/*/*.jsonl の usage を足せば同じ3つの数字が出る（activecore の startup-cost.py、hitokraft の breakdown.mjs）。

出典: Zenn — activecore（常駐費の内訳） ／ Qiita — Shinn_Matsumoto（claude_task.sh） ／ Zenn — hitokraft（40億トークンの内訳）
