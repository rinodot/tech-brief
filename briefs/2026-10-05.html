Claude Code を毎時 claude -p で起動し、仮説→検証→本番投入まで無人で回す型 — 起動するかは LLM の外の決定表が決め、マージと push は専用スクリプト 2 本だけ、回数と費用の上限は policy.yaml に固定。1 サイクル 5〜8 分・2〜3 ドル。事故は「何もしない PR を 1 日 34 本マージ」と「外部コマンドが 52 分ハング」の 2 件

— 9/29 既報のルーティン（クラウド側の定期実行）に対し、手元の cron＋headless で組む無人運用の完成形。「起動判定・上限・本番操作」を LLM の外に出す設計がそのまま写せる。

toshipon氏（10/4）。スケジューラが毎時 0 分に precheck.sh を実行し、終了コード 0 のときだけ claude -p を起動する。何をするかは決定表（RETIRE→SCORE→BACKTEST→…→WAIT の 10 行動）が返し、LLM は決められた作業だけを行う。マージとデプロイは専用スクリプト 2 本を経由したときだけで、gh pr merge と git push は --disallowedTools で禁止。回数と費用の上限は policy.yaml に書く（1 サイクル $50、1 日のマージ 12 回など）。実績は 1 サイクル 5〜8 分・2〜3 ドル。

事故は 2 件。自分のログを起動判定の材料にしていたため「何もしない PR を 1 日に 34 本マージ」→ 判定材料から自分のログを外し、決定表が行動を返すときだけ起動する。「外部コマンドが 52 分ハングし、ロックを握り続けた」→ 外部コマンド全部にタイムアウト。含意: 無人ループは「起動するか」「どこまで使うか」「本番に触るか」を LLM の外で決める。対象はクオンツ研究（実資金）で n=1、費用は著者の自己申告。

試すなら: cron に 0 * * * * precheck.sh && run.sh の形で置き、precheck.sh は「やることがあるか」を終了コードで返すだけにする → run.sh は claude -p "$prompt" --model opus --permission-mode acceptEdits --max-budget-usd 3 --allowedTools "Read" "Edit" "Write" "Glob" "Grep" "Bash(git add:*)" "Bash(git commit:*)" "Bash(gh pr create:*)" "Bash(flutter test:*)" --disallowedTools "Bash(git push:*)" "Bash(gh pr merge:*)" "Bash(firebase deploy:*)" → push とデプロイは自分のスクリプトで、テスト成功時だけ → 外部コマンドは timeout 600 … で包む（--max-budget-usd（print mode 専用、サブエージェント分も含む）・--allowedTools／--disallowedTools・--permission-mode acceptEdits は docs/en/cli-reference で確認済み。記事のコマンドと policy.yaml は本文、数字は n=1）。

MCP ツールの結果は「欲しい項目だけ返す」を強制できるかで約 60 倍違う — GitHub の PR 5 件を取る同じ作業で、REST 型 MCP（ツール 54 個）はツール結果 26,993 トークン・呼び出し 10 回、GraphQL 型（4 個）は 419 トークン・1 回。REST でも ?fields= を付ければ同じだが、Haiku 4.5 は 3 回中 2 回付け忘れた

— 9/22 の「ツール定義のトークン」の続きで、今度は結果側。自作 MCP や Firebase MCP の返り値を絞る設計の根拠になる。

野口氏（joe_re、10/4）。GitHub MCP Server（REST）と Apollo MCP Server（GraphQL）に同じ依頼を出すと、1 回の費用は $0.0724 対 $0.0089（Haiku 4.5）、4 モデルで 7.0〜11.2 倍。模擬バックエンドでは REST の ?fields= が任意なので Haiku 4.5 は 3 回中 2 回付け忘れ、結果が 3.6〜3.9 倍に膨らんだ。含意: 差は方式でなく「項目の絞り込みを強制できるか」。Phase 1 は 120 回、Phase 2 は各 3 回。

試すなら: 自作 MCP の一覧系ツールに fields と limit を必須引数にし、省略時は最小項目だけ返す → Claude Code で同じ依頼を 3 回ずつ流し、/usage の Session の入力トークンを前後で比べる → 使わない MCP は alwaysLoad: false で tool search 側に回す（Claude Code 2.1.283・apollo-mcp-server 1.14.0・GitHub MCP Server v1.12.2、数字は記事本文、Phase 2 は一部条件のみ。再現は github.com/joe-re/graphql-mcp-benchmarks）。
