Anthropic が「claude.ai を2週間で3.1倍速くした」手順を公開 — Slack の常設指示で Claude を150本超のスレッドで並列に走らせ、Valgrind の命令数など決定論的な指標だけを追わせ、機能フラグ＋人の承認1回で約3,000変更をマージ

— 「Claude が測れるものは速くできる」の型。自分のアプリの起動時間やテスト時間にそのまま写せる。

claude.dev ブログ（Raymond Wang 氏ら、9/23）。初回ロード 3,085→550ms、Cowork のメッセージ送信 928→48ms、13指標の幾何平均で 3.1倍（いずれも p75）。Desktop アプリの起動も 6,310→3,328ms。やり方は Slack チャンネルに常設の指示を置き、Claude（社内モデル、Opus 5.5 相当）が非同期で 150本超のスレッドを回す。

鍵は指標の選び方。壁時計の時間はぶれるので、node --predictable で走らせた Valgrind の命令数、React のコミット回数、DOM 変更回数など決定論的な数を測らせ、CI には「前回より悪化したら落ちる」ラチェットを置いた。出荷は機能フラグ＋自動レビュー＋人の承認1回、社員→1%→全員の段階公開で約3,000変更。含意: 人が決めるのは「何を測るか」だけで、下げる作業は並列に任せられる。自分のアプリなら起動時間・テスト時間・ビルド時間が同じ型に乗る。

試すなら: 自分のアプリで Claude が読める数値を1つ決める（flutter test の所要秒数、CI の実行時間、integration test のフレーム時間など）→ CLAUDE.md に「変更前後で <計測コマンド> を実行して数値を報告し、悪化したら戻す」を書く → CI に前回値より悪化したら失敗するチェックを置く → 変更は機能フラグと人のレビュー1回を必須にする（手順と数字は記事本文で確認済み。claude.dev は Anthropic のエンジニアリングブログで、ヘッダーから code.claude.com/docs に繋がる）。

出典: claude.dev Blog — How we made claude.ai 3x faster in two weeks

GENDA のエンジニアが自作のオーケストレーション（1,477行・7 Skills）を 312行まで削って最終的に捨てた — Opus 5.5 は「仕事を丸ごと渡して走らせる」方が良く、司令塔役との往復がボトルネックになった

— 昨日の公式手引き「制約を減らす」の実例。CLAUDE.md とサブエージェントの設計を見直す材料。

okkun0524氏（9/24）。Claude Code と Codex を役割別に走らせる自作プラグイン baton を、1,477行・7 Skills から 312行・1 Skill に削り、最後はやめた。理由は ①検証指示の明示は過剰検証を招く ②Fable 5.1 の値下げで安いモデルを割る旨味が消えた ③Opus 5.5 は仕様を丸ごと渡す方が良く、司令塔との往復が遅い。残したのは CLAUDE.md の原則とサブエージェント委任。費用は実測なし。含意: プロンプトガイドが更新されるたびに、指示と自作の仕組みを削れないか見る。

試すなら: CLAUDE.md とサブエージェントの本文から「必ず〜を検証せよ」系の指示を一度外し、同じタスクで出力と /usage の減り方を比べる → 役割分担が要るなら常駐ペインでなく単発のサブエージェントに → 公式の Prompting Claude Opus 5.5（9/24掲載）と照らして指示を毎回見直す。

VRAM 10GB の RTX 3080 で 27B モデルが 64 tok/s — Qwen3.8-27B を三値（ternary）量子化した Bonsai 2 は 7.21GB の GGUF で全層が VRAM 9.6GB に載る。ただし専用フォークの llama.cpp が必要

— 12〜16GB の GPU で 27B 級を回す選択肢。品質「98.2%」はベンダー自己申告で、日本語の数量詞の読み違いも出る。

masa-555氏（9/23）。HF の prism-ml/Ternary-Bonsai-2-27B-gguf の PQ2_0（7.21GB）で VRAM 9.6GB・生成 64 tok/s。PTQ1_0（5.95GB）なら 8.4GB・53 tok/s。素の llama.cpp では動かず PrismML のフォークが要る。品質「FP16 の 98.2%」はベンダー発表で、著者は単位換算ミスと中国語混入を見た。含意: 速度≠完了時間。9B の Ornith-1.5（85.9 tok/s）は同じ課題を 8 分、Bonsai 2 は 16 分。

試すなら: git clone https://github.com/PrismML-Eng/llama.cpp（prism ブランチ）→ cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=<自分のGPUの値。RTX 30 系は 86> -DCMAKE_BUILD_TYPE=Release && cmake --build build -j$(nproc) --target llama-server → HF から PQ2_0 の GGUF（Apache 2.0）を取って llama-server -m <gguf> --jinja -ngl 99 -fa on -c 65536 -ctk q8_0 -ctv q8_0（記事のコマンド。「Stock llama.cpp will not run these files」は HF のモデルカードで確認済み）→ 自分の日本語タスクで 9B 級と完了時間を比べる。

出典: Qiita — VRAM 10GB の RTX 3080 で 27B が 64 tok/s 出た — ternary 量子化モデル Bonsai 2 実測ノート
