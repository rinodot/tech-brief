16GB の GPU に 16.2 GiB のモデルを載せると一部が CPU に溢れて 6.4 tok/s、12.85 GiB のモデルなら 88.5 tok/s — 別モデル同士の比較だが、溢れたかは /api/ps の size と size_vram で分かる。num_ctx 未指定だと長いプロンプトは先頭から黙って切られる

— 下の特集③の実例。式で VRAM に収まるか先に計算し、API で溢れを確かめる手順が今日から使える。

chiaki_ai_lab氏（10/1）。RTX 5060 Ti 16GB・Ollama 0.33.2 で、gemma3:27b（16.2 GiB）は 6.4 tok/s、gpt-oss:20b（12.85 GiB）は 88.5 tok/s。別モデル同士の比較だが、載ったかは /api/ps で分かる。落とし穴は 3 つ: num_ctx 未指定だとプロンプトが先頭から黙って切られる、num_thread 未指定で PC が操作不能、Docker 越しの stream: false は切られる。含意: 速さの前に「載っているか」を確かめる。

試すなら: curl localhost:11434/api/ps で size と size_vram を比べ、差があれば溢れている（ollama ps の PROCESSOR 列でも可） → 溢れるなら特集の式で num_ctx を下げるか KV を q8_0 に → リクエストの options に num_ctx（既定 4096）と num_thread を毎回入れ、長い生成は stream: true（size_vram・keep_alive: 0・既定 4096 は Ollama の API docs と FAQ で確認済み。数字は記事本文、n=1）。

特集: VRAM と帯域の内訳 — 1 層溢れただけで 19 分の 1 になる理由を、KV キャッシュの式 1 本で読む

VRAM に載るのは重み・KV キャッシュ・作業領域。文脈で増えるのは KV。kas_blog氏（9/20）の式は M_KV＝B×T×L×2×H_KV×d_head×s（同時系列数×系列長×層数×K と V の 2×KV ヘッド数×ヘッド次元×バイト数）。32 層・32 KV ヘッド・128 次元・4,096 トークン・2 バイトで 2 GiB、1 トークン 512 KiB。llama3.1:8b なら 128 KiB。

減らせる変数は 2 つ。H_KV は GQA（複数の Q ヘッドで 1 つの KV ヘッドを共有）で減り、同氏 9/24 の例は 8,192 トークンで MHA 4 GiB→GQA 1 GiB→MQA 128 MiB。Qwen3.6-35B-A3B はフル注意 4 層に 1 層・KV ヘッド 2 で 1 トークン 20,480 バイト、128K でも +2.59 GiB（istb16氏、10/3）。s は KV 量子化で q8_0 なら半分。

崖は載り切らない瞬間に来る。RTX 5080 16GB の llama3.1:8b Q4_K_M を 65,536 トークンにすると、KV が f16 なら 16.7GB で溢れて 26 tok/s、q8_0 なら 12.5GB に収まって 132 tok/s（図鑑）。9/15 既報の RTX 4070 12GB も、-ngl 42→44 層で溢れた途端プロンプト処理が 319→16.5 tok/s。溢れた分は PCIe 越しに CPU 側のメモリを読むので桁が落ちる。

載り切っても上限は帯域。生成は 1 トークンごとに重み全部を読むので、速度の上限≈帯域÷読むバイト数。内蔵 GPU の Qwen3-8B Q4_K_M（4.68 GiB）は 6.04 t/s（汐見セツ氏、9/24）、同じ 8B Q4 が 16GB カードでは 128 tok/s。プロンプト処理は計算律速で、128K なら 21〜24 分（istb16氏）。含意: 文脈長は「式で載る T」まで、速度は帯域の上限まで。量子化・GQA・KV 量子化は全部「読むバイト数」を減らす同じ手。

試すなら: ①nvidia-smi --query-gpu=memory.used,memory.total --format=csv で空きを見る ②モデルの層数・KV ヘッド数・ヘッド次元（GGUF のメタデータか HF のモデルカード）を式に入れ、空き VRAM−重みで使える T を出す ③Ollama は OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0、llama.cpp は -fa on -ctk q8_0 -ctv q8_0 で s を半分に ④ollama ps の PROCESSOR が 100% GPU か確認し、溢れていたら num_ctx か -ngl を 1 段ずつ下げて tok/s を記録する（式と例の数字は各記事本文、図鑑は 6/6 公開・9/24 更新。OLLAMA_KV_CACHE_TYPE の f16／q8_0／q4_0 と ollama ps の表示は docs.ollama.com/faq、-fa／-ctk／-ctv／-ngl は llama.cpp の arg.cpp で確認済み。図鑑のページには Amazon リンクあり、istb16氏の機材は 93.6 GiB の Vulkan 環境で絶対値は写せない）。
