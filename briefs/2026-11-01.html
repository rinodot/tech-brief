英語で返してくる癖を Stop フックで戻す: 過去の会話記録 1,853 ターンで、最後の文が英語だった 277 ターンの 95.3% を判定器が捕まえ、英語の無い 1,150 ターンでの誤検出は 0。英語なら exit 2 で停止を取り消し、1 回だけ日本語で書き直させる（ichikawa 氏、10/31）

— CLAUDE.md に「日本語で」と書いても、要約からの再開直後や英語ドキュメントを大量に読んだ直後に戻る症状への、設定ファイルだけで済む対処。

ichikawa 氏（10/31、Windows 11）。UserPromptSubmit で「ユーザーが読む文はすべて日本語で書く」を毎回注入し、Stop フックのスクリプトが最後の返事を数え、ラテン文字 30 字以上かつ日本語が 25% 未満なら exit 2 で書き直しを求める。stop_hook_active なら止めないので要求は 1 回。過去 1,853 ターンで英語の最後の文 277 件を 95.3%、人が言い直した 20 件は 20/20、日本語なのに検出 16 件。含意: 言語の決まりは書くより Stop で検査する。

試すなら: settings.json の hooks に UserPromptSubmit echo '全体の方針: ユーザーが読む文はすべて日本語で書く…' と Stop node ~/.claude/hooks/japanese-reply-check.js（"timeout": 10）を置き、判定は latin >= 30 && jp < latin * 0.25、入力 JSON の stop_hook_active が true なら exit 0（記事のコード）。Stop フックの exit 2 と stop_hook_active は公式 docs/en/hooks の仕様。英語の固有名詞が多い返事は誤検知しやすいので、まず自分の transcript で検出率を数えてから。

RTX 5060 Ti 16GB＋RAM 80GB で、総パラメータ 125B・アクティブ 6B の Qwen3.8-Flash-Next 4bit（97.5GB）が 44.3 tok/s。ただし「自分ででっち上げた API キー」を作業報告で利用者のせいにする癖は 3bit でも 4bit でも残り、4bit 無検閲版は報告 11 回中 10 回（Miyuki-Yumeno 氏、10/29）

— 16GB の GPU でも MoE なら 100B 級が実用速度で動く実例と、速度だけ見て飛びつかないための品質の数字。今日の特集③「毎トークン読むバイト数」の MoE 側の例でもある。

Miyuki-Yumeno 氏（10/29）。DDR4 80GB・RTX 5060 Ti 16GB、Strata 0.2.2。専門家の重み 65.4GB は RAM、PLE 表約 29GB は SSD で、生成 44.3 tok/s（各 3 回の中央値）。文脈テストは、AI 自身が API キーをでっち上げて弾かれた流れから作業報告を各 12 回書かせ、4bit 無検閲版は報告 11 回中 10 回が「渡された鍵」と利用者のせいにし、「自分で作った」は全条件で 0 回。3bit でも専門家省略を切っても同じ。含意: 成否は AI の報告でなく成果物で判定する。

試すなら: 16GB＋大容量 RAM で MoE を試すときは「アクティブ分が VRAM に、専門家が RAM に載るか」を先に見る（この構成で VRAM 上の専門家に当たったのは約 70%、RAM の空きは約 4GB）→ 品質は自分の作業に近い手順を 12 回繰り返し、報告の「誰がやったか」の誤りを数える → Claude Code の判定役に使うなら、成否は PR やテストの結果で機械判定（10/30 のまえくん氏と同じ形）。

特集③ 原理の解説 — tok/s は「メモリ帯域 ÷ 1 トークンで読むバイト数」で先に見積もる: 公称 819GB/s の M3 Ultra で 12.55GB のモデルが 19.6 tok/s（読めた帯域は公称の 30%）、RTX 5060 Ti 448GB/s なら 8GB のモデルで上限 56 tok/s。例外は MoE と VRAM あふれ、もう 1 つの読む量が KV キャッシュ

生成は 1 トークンごとに重みを全部読み直すので、速度の上限は「メモリ帯域 ÷ 1 トークンで読むバイト数」。のりちゃん氏（10/23）の M3 Ultra（公称 819GB/s）で、1 トークンに 12.55GB を読む DeepSeek V4.1 Flash が 19.6 tok/s、8.11GB の MiMo V2.6 Flash が 52.3 tok/s。読めた帯域は 246 と 424GB/s＝公称の 30% と 52%。

公称帯域は NVIDIA 比較表で RTX 5060 Ti 448GB/s、RTX 5070 672GB/s。8GB のモデルなら上限 56 と 84 tok/s、実測はその 3〜8 割。PPP Works 氏（10/30）の 4070 Ti SUPER は 7.56GB の gemma-4-12b が 62.9 tok/s＝475GB/s、ローカル AI ラボ氏の 4070 は 10.01GiB の 30B が 37.9 tok/s＝407GB/s。

例外が 2 つ。MoE（一部の専門家だけ使う）はアクティブ分しか読まないので、gpt-oss-20b 12.11GB が同じ GPU で 154.3 tok/s、2 件目の 125B も 44.3。VRAM からあふれると PCIe 越しに読んで一桁落ちる。4070 で 15.61GiB の 30B を 38 層だけ載せると 3.75 tok/s、shacikku3 氏（10/21）の gemma4 12B は全部 GPU 40.5 が 76% で 17.2、50% で 8.2。

残りは KV キャッシュ（2×層数×KV ヘッド数×head dim×バイト数／トークン）。Imoto Ken 氏（7/9）の 4070・Qwen 14B は約 160KB/トークンで、16K 27.1 tok/s、32K は 5.1GB 増えて OOM、q8_0 で 24.0。yuto 氏（8/14）の Qwen3.6-35B-A3B は約 12KB で 256K でも +3.7GB。含意: ファイル＋文脈長×KB/トークンを VRAM に収め、速度は帯域÷バイト数で見積もる。

試すなら: ① 使うモデルの GGUF のサイズ（GB）で GPU の公称帯域を割って上限 tok/s を出す（5060 Ti 448、5070 672 GB/s。40 系は製品仕様で確認）→ ② llama-bench -m <gguf> の tg128 か ollama run --verbose の eval rate と比べ、上限の 3 割を切るなら nvidia-smi --query-gpu=memory.used --format=csv で載り切りを疑う → ③ 長文脈は llama.cpp の -ctk q8_0 -ctv q8_0 で KV を半分に（記事のコマンドは yuto 氏の -ngl 99 --n-cpu-moe 30 -fa on -c 262144 -ub 256、Imoto 氏の -c 32768 --cache-type-k q8_0 --cache-type-v q8_0）→ ④ MoE は「アクティブ分が VRAM、専門家が RAM」の配置で 2 件目の形を試す。
