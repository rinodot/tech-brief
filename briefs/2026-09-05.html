圧縮後の「ルール忘れ」は SessionStart の compact で塞ぐ — PreCompact では効かない

— 長いセッションで自動圧縮が走ったあと、それまでの合意がすっぽ抜ける現象への正しい対処。

自動圧縮が走ると、CLAUDE.mdの規則は残るのに「このタスクではAを優先」といったセッション内の合意が要約から落ち、規則の適用文脈が消える。よく提案されるのがPreCompactフックでactive-rules.mdを標準出力に流す設計だが、公式リファレンスはPreCompactを「情報提供のみ」と明記しており、stdoutもadditionalContextも圧縮には入らない（できるのは終了コード2で圧縮を止めることだけ）。

効く経路はSessionStartフックのcompactマッチャだ。圧縮後にセッションが再開する瞬間に発火し、コマンドが標準出力へ書いた平文がそのままClaudeの文脈に足される。公式ガイドにも「圧縮後に文脈を再注入する」レシピとして載っている。実例はplayparkの8/18のZenn記事で、PreCompactはブランチ名・git status・直近コミットをファイルに書くだけ、注入はSessionStart側に寄せている。含意: 流し直すのはCLAUDE.md全体ではなく、このセッションで効かせたい制約を3〜5行に絞る。

試すなら: .claude/settings.json に {"hooks":{"SessionStart":[{"matcher":"compact","hooks":[{"type":"command","command":"cat active-rules.md"}]}]}}。active-rules.md には今のセッションの制約だけを3〜5行。

出典: Claude Code docs — Re-inject context after compaction

/skill-doctor — 読み込んだSkillsのうち使われていないものと、その文脈コストが見える

— 昨日書いた「スキル1つで毎回100〜200トークン」を、自分の環境で測れるようになった。

9/4公開のv2.1.261に入った。/skill-doctorを打つと、読み込まれているSkillsのうち一度も使われなかったものと、それぞれのコンテキストコストが出て、刈り込む判断ができる。Skillsは説明文が常駐する仕組みで、積み上がると毎ターンの費用になる。同リリースで、Bashとバックグラウンドタスクの出力上限をbashOutputMaxChars／taskOutputMaxCharsで最大128K文字にできる。含意: 「評価はスキルありで通り、なしで落ちる」の、なし側を作る道具。

試すなら: いつものプロジェクトで /skill-doctor。使われていないと出たものは ~/.claude/skills/ から別フォルダへ退避して1週間様子を見る。

出典: claude-code v2.1.261

ローカルLLMのtok/sは「捨て実行1回・3回計測」で測る — 初回は最大300倍ずれる

— モデル選定を初回の数字でやると、判断を丸ごと間違える。

yamada-ai-dev氏が9/4にZennで、RTX 4070 Ti（12GB）とOllama v0.33.2で5つの罠を実測した。初回はモデル読み込みで遅く、qwen3:8bは2.19 tok/s、ウォームでは38.09 tok/s。gemma4:12bは初回240秒でタイムアウト、ウォームで44.51 tok/s。ollama psが100% GPUでも、num_ctx=131,072ではGPUメモリがRAMへ退避し46.6から16.4 tok/sに落ちる。含意: 表示でなく測った数字で決める。

試すなら: 計測前に同じプロンプトを1回捨て実行し、3回以上測って min／mean／max を記録する。ollama ps の GPU% と think: false の受理（qwen3:4bでは全26件無視された）は信用せず、出力で確認する。

出典: Zenn — ローカルLLM速度計測の罠
