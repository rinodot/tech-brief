サブエージェントの書き込みを本当に止める設定はどれか — yorusuzu 氏が検証用 11 体を claude -p で実測（10/10、計 $0.06）: tools から Write を外しても Bash のリダイレクトで書ける、親の deny は Edit(...) なら親も子も止まるが Write(...) は素通り、子の permissionMode: plan は親が acceptEdits だと無視される、孫の起動は tools に Agent を書かなければ起きない

— 9/14 既報「deny の Write(パス) は参照されない」をサブエージェントまで広げた実測。9/20 特集①の worktree 隔離や 10/9 既報の分担で、子に渡す権限を決める根拠になる。

検証用の子 11 体を haiku で 2 回。disallowedTools: Write, Edit はツール自体が消える。親の deny は Edit(...) なら親も子も止まり、Write(...) は書けた。tools: Read, Bash の子はリダイレクトで書け、Edit の deny で止まる。permissionMode: plan は親が acceptEdits なら無視される。PreToolUse（exit 2）は両方止める。含意: 子の書き込み制限は Edit(...) の deny かフックで決める。Windows・各 1 回。

試すなら: 読み取り専用にしたい子の .claude/agents/scoper.md に disallowedTools: Write, Edit, Agent（孫も止める。入れ子の既定は 3 層、CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 で全体を止められる）→ settings.json の permissions.deny に "Edit(src/**)" を足す → claude -p "scoper で src/ を調べて要約して" --max-budget-usd 1 の後に git status で何も変わっていないこと、Bash の > 経路も止まったことを確かめる → permissionMode: plan は親の mode に依存するので、確実に止めたい経路は PreToolUse の command フック（exit 2）に（frontmatter のキーと入れ子の既定は docs/en/sub-agents、deny の挙動は記事）。

Claude Code を手元の Ollama モデルで動かす公式手順 — ollama launch claude --model glm-5.3-flash の 1 行（docs.ollama.com）。settings.json の env に ANTHROPIC_BASE_URL・ANTHROPIC_AUTH_TOKEN と ANTHROPIC_DEFAULT_HAIKU_MODEL などを書けば、haiku／sonnet／opus の枠ごとに別モデルを割り当てられる（uhu 氏 10/10）。条件は tools 対応モデルと 64k 以上の文脈

— 9/10 既報「軽い観点は Ollama」を Claude Code 本体で。使用枠を減らさない下書き・要約・ログ読みを 12〜16GB の GPU で回す入口。

Ollama 公式の統合ページ。ollama launch claude が Claude Code を Ollama 向けの環境変数つきで起動する。条件は tools 対応モデルと 64k 以上の文脈、例に glm-5.3-flash・qwen3.5。uhu 氏（10/10）は settings.json の env で枠ごとに別モデルを割り当て、既定外のモデルは 200K で圧縮されるので [1m] を付けると書く（経験則）。含意: 使用枠を使わない作業を分ける道が公式にある。WebSearch など一部ツールは非対応。

試すなら: ollama pull glm-5.3-flash → 文脈を OLLAMA_CONTEXT_LENGTH=65536 で起動した Ollama に対し ollama launch claude --model glm-5.3-flash → /status で接続先が localhost:11434 か確認 → 枠を分けるなら settings.json の "env" に "ANTHROPIC_BASE_URL": "http://localhost:11434"、"ANTHROPIC_AUTH_TOKEN": "ollama"、"ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-5.3-flash" を書き、haiku 指定の作業（要約・ログ読み・サブエージェントの scoper）だけローカルに流して、同じ作業の品質を 1 週間比べる（コマンドと変数は docs.ollama.com/integrations/claude-code と docs/en/model-config、OLLAMA_CONTEXT_LENGTH（既定 4096）は docs.ollama.com/faq。uhu 氏の記事は :cloud モデル中心で手元のデータが外に出る点に注意）。

特集④ 実例の分解 — 何を分担し、どこで壊れ、何で測ったか。5 か月・2 か月・17 日・一晩の 4 つの運用記録を同じ 3 段で読む

分担。Cockroach Labs（10/9）は issue を患者に見立て、実装役とは「別のインスタンス」のレビュー役、30 分ごとの停滞巡回役、差し戻し 3 回超で動く安全性レビューを置いた。welchi 氏（10/10）は作業役とレビュー役を別会話に。閉店後 開発者氏（10/11）は読み取り専用の点検を先に、実装は領域で分けた worktree で合流。共通点は、書く役と判定する役を別インスタンスにし、状態を会話の外に置くこと。

どこで壊れたか。Cockroach では指示文書 約 10 万語の 23% が「消しても結果が変わらない」と判定され、issue 1777 は 1 行の修正に差し戻し 11 回・2 日。閉店後 開発者氏は単体テスト 1,450 件が通っても効果音が鳴らず（テストも同じエージェントが書いた）、AI の自己採点は点検のたびに下がった。cucinakiyo_ai 氏（10/10）の無人ループは「拒否がなければ合格」で未実行の回まで合格にし、成功報告 23 件中 13 件が否定された。3 種: 書き手＝判定者、測れない回を数える、文書の肥大。

何で測ったか。Cockroach は Db2 対応が 2 日弱・$4,172（Oracle は 9 か月・約 16 万ドル）、コミットの 85% がパイプライン製。閉店後 開発者氏はボット 3 回で −19% に見えた指標が 6 回で −5%、境界の判定は 48 回に増やした。welchi 氏は 2 週間の不満 184 件を仕組みに変え、指標は週 1 枚、正解データは判定器にも見せない。cucinakiyo_ai 氏は判定器に「測れていない」の箱を足した。

移せるのは 4 点。レビューは別インスタンスで、まず読み取り専用から。差し戻しは回数で止める（3 回超で人に戻す）。測定は回数を増やし測定器を先に疑い、測れなかった回を合否から外す。指示文書は月 1 回棚卸し。welchi 氏も「普通の業務開発なら 2〜3 並列で十分」と書く。4 本とも n=1・宣伝つき。

試すなら: .claude/agents/reviewer.md の冒頭に「あなたは実装したセッションとは別のインスタンス。読み取り専用で、直さず報告する」と書き、1 件目の disallowedTools: Write, Edit を付ける → 差し戻しは Stop フックの判定役で数え、3 回を超えたら ok=false をやめて人に戻す（10/8 既報の CLAUDE_CODE_STOP_HOOK_BLOCK_CAP と対で使う）→ 自動テストや無人ループの結果は「試した」「測れなかった」「通った」の 3 列で台帳に残し、通った数だけで判断しない → wc -w CLAUDE.md .claude/skills/*/SKILL.md を月 1 回記録し、増え続ける文書は削る候補にする（数字は各記事本文。Cockroach の issue 1 件あたりの金額は分母が記事内で合わないので使っていない）。
