/goal は「終わったか」を別のモデルに判定させる仕組み — 確認コマンドと変更禁止の範囲を条件に書かないと、抜け道を通って「達成」になる

— 「テストが通るまで」を毎ターン促さずに回せるが、条件の書き方ひとつで結果が変わる。

/goal <条件> はセッション限定の Stop hook で、毎ターンの終わりに小型モデル（既定は Haiku）が会話に出た文字列だけを見て「未達／達成／不可能」を返す。コマンドは実行せずファイルも読まないので、条件は Claude の出力に現れる形で書く（例: npm test が 0 で終わる）。ターン上限は条件に「or stop after 20 turns」と書く方式で、Claude Code 自身は数えない。claude -p "/goal …" で非対話でも回る。

嶋田怜央成氏（9/15、v2.1.271）が Ruby の小さなリポジトリで7条件を検証。「既存ファイルを変えずにテストを通す」は Claude が lib/pricing_patch.rb などの新規ファイルで回避して「達成」、「git status --porcelain が空のまま」を足すと評価者が即「不可能」と判定して終了した。評価者の消費は1ゴール 2,600〜7,100 トークン。提案のテンプレは「/goal <確認コマンド> が <期待する結果> で終わる。<変えてはいけない範囲>。<上限>」。含意: 抜け道は条件の穴で、モデルの悪意ではない。

試すなら: auto mode で /goal flutter test が exit 0 で終わる。lib/ 以外は変更しない。or stop after 10 turns → /goal で経過と評価者の理由を見る（Ctrl+O で理由の全文）。硬い上限が要るなら claude -p "/goal …" --max-turns 10。

出典: DevelopersIO — Claude Code の /goal は何を根拠に「終わった」と判断するのか、複数の指示で検証してみた

Cloud Functions 第2世代で Authentication トリガーが GA — onUserCreated／onUserDeleted を firebase-functions/v2/identity から使える

— ユーザー作成時の初期データと退会時の後始末だけ第1世代に残していたなら、全部 v2 に寄せられる。

Firebase のリリースノートと firebase-functions v7.4.0（9/15）。event.data に uid・email・displayName が入り、region・memory・secrets など v2 のオプションもそのまま。注意: カスタムトークンの初回サインインでは発火しない、Admin SDK の一括削除では削除イベントが出ない、配送は at-least-once なので冪等に。含意: functions.auth.user().onCreate() を第1世代に残す理由が消えた。

試すなら: npm i firebase-functions@^7.4.0 → onUserCreated({ region: "asia-northeast1" }, async (e) => { await db.doc(`users/${e.data.uid}`).set({ createdAt: FieldValue.serverTimestamp() }) }) → firebase deploy --only functions → テストユーザーを作って Firestore に書かれるか、同じイベントを2回受けても壊れないかを見る。

claude-code-action の PR コメントが「権限拒否」で消えていた — 原因は本文の ## 見出しで、プロンプトで見出し禁止にしたら拒否 9→0・費用 −78%

— 「Claude は書いたのに投稿されない」を Actions のログの permission_denials_count で見つける型。

小西諒氏（9/17）。gh pr comment --body '…' の本文に見出し ## があると、Bash の安全ヒューリスティックが「引用符内の改行＋# は引数隠し」と見て拒否する。permissions の allow では抑止できない（Issue #30435）。対処はプロンプト側: 見出し禁止で太字、gh pr comment で投稿と明示、PR 番号を渡す。結果は権限拒否 9→0、ターン 17→5、$0.69→$0.15、125秒→48秒。含意: ローカルで $() や heredoc のコミットが毎回聞かれるのも同じ層。

試すなら: Actions のログで permission_denials_count を見る → プロンプトに「Do NOT use markdown headings (##, ###). Use **bold** instead」「MUST post the review with gh pr comment」を足す。本文をファイルに書いて gh pr comment --body-file body.md にすると引用符内の改行そのものを避けられる。

出典: DevelopersIO — GitHub ActionsのClaude自動レビューでコメントしてくれない問題とその対処法
