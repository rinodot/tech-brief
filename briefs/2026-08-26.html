Claude Code v2.1.243 — キャッシュTTLが設定可能に、サブエージェント運用に効く回

— サブエージェントを常用しているなら、消費と可視性の両方が今日から変わる。

8/25までに出たv2.1.243に、運用設計まわりの変更がまとまって入った。効くのは2つ。1つはキャッシュ制御で、promptCacheTtlとsubagentPromptCacheTtlが追加され、APIキー／クラウド利用ならメイン会話を1時間キャッシュしたままサブエージェントは5分に据え置ける（プロンプトキャッシュ＝前回の文脈を再利用して課金を抑える仕組み）。もう1つは/tasksにサブエージェントの実行モデルとエフォートが出るようになった点だ。Hooksでは、if条件がバッククォートや$()を含むコマンドに誤って一致する不具合が直った。/usageにはLoopsの内訳（loop別の実行回数・総トークン・1回あたり）が加わり、暴走した/loopを見つけられる。

配布物も軽くなった。インストーラがzstd圧縮になりLinux x64で340MB→約75MB、常駐メモリも1セッションあたり40〜70MB減った。翌日のv2.1.245はglibc 2.44系での起動クラッシュ修正のみ。含意: キャッシュTTLは消費に直結する。サブエージェントを多用するなら真っ先に見る値だ。

出典: Claude Code changelog

訂正: FlutterFireの言語移行はfirebase_core単体ではなかった

— 昨日の2番に誤りがあった。実際は5パッケージが同時に動いている。

昨日「上がったのはfirebase_core単体」と書いたが、これは誤りだった。8/24の同じ時刻に firebase_auth 6.6.0、cloud_firestore 6.9.0、analytics 12.5.0、cloud_functions 6.4.0 も出ている。進み方は揃っておらず、Kotlin/Swiftの両方が済んだのはcoreとauthのみ、analyticsとfunctionsはSwift化だけ、firestoreは言語移行なしだ。storage・messaging・crashlyticsは8/3のまま手つかず。含意: 過渡期なのでパッケージ単位で判断したい。

出典: pub.dev

Perplexityが完全ローカル動作のエージェントを配布 — 動かすのはQwen3.8-27B

— 「ローカルで足りる」の製品化。手元で回した分は課金されない設計だ。

Perplexityが8/25、自社エージェントを完全にオンデバイスで動かす「Portable Computer」をPro/Max向けに公開した。主対象はNVIDIA DGX Spark（GB10、統合メモリ128GB）で、RTX搭載PCへの対応も予告。動かすモデルはQwen3.8-27Bと自社で追加学習したPPLX 27B。ローカル処理はクレジット課金なしで、必要なときだけクラウドへ引き上げる。現状Linuxのみ。含意: 「手元で済ませ、足りないときだけ上げる」が製品の既定形になってきた。

出典: Perplexity
