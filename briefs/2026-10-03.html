Claude Code を 9 セッション並べて一晩半で 581 コミット・テスト 1,310 件全部緑 — でもアプリは通しで動かなかった。衝突を防いだのは「1 ファイル 1 所有者・契約が先・書いた本人はマージしない」の 5 つ、足りなかったのは最初に通す e2e 1 本と「件数でなく終了コード」の報告

— 9/27 特集②「実装は並列、マージは直列」と 9/30 の 10 セッション運用を、失敗まで書いた実例。並列を増やす前に「統合で緑を測る」を入れる。

Shune氏（10/2）。tmux の 1 ウィンドウを 9 ペインに割り、それぞれで独立した Claude Code を起動（統括の Lead 1 体＋担当 8 体。機能を縦に通す 5 体と共通層 3 体、Max 20x の 1 アカウント）。衝突を防ぐ仕組みは 5 つ: 1 ファイル 1 所有者、契約（CONTRACTS.md）が先、[PLAN][READY] など 14 種のタグ付きメッセージ、書いた本人はマージできない、事故は PITFALLS.md に番号付きで残す（46 件、うち 17 件は今回起きた）。結果は一晩と半日で 581 コミット・マージ 98 回・テスト 1,310 件が全部緑。

それでも「部分は全部緑なのに、全体が動かない」。壊れたのは担当と担当の境目で、CONTRACTS.md は最初の 1 時間で 9 回改版され今は v1.12。対策は 3 つ: 「起動→作業作成→ターミナル表示→片付け」の通し 1 本を最初に e2e にする、提出条件を「統合ブランチに載せて新しい worktree で make check と e2e が通る」にして緑を統合側で測る、報告は件数でなく終了コード。含意: 並列の数より先に、統合で測る 1 本を置く。著者も「半分は実験のつもりだった」と書く n=1。

試すなら: まず 2〜3 セッションで、①着手前に CONTRACTS.md（境界の API と各ファイルの所有者）を書く ②PITFALLS.md に事故を番号付きで追記し、番号は振り直さない ③提出は「統合ブランチで新しい worktree を切って make check && make e2e; echo $? が 0」で判定し、報告にその終了コードを書かせる ④通しの e2e は最初の 1 本目に作る（5 つの仕組み・数字・提出フォーマットは記事本文。9 体にした効果の比較はなく、著者も実験と明記）。

Raspberry Pi 5 の CPU だけで動く個人メモの RAG — 日本語メモでは全文検索（SQLite FTS5）が埋め込み検索より強く（recall@5 0.88 vs 0.83）、両方を RRF で合わせると 0.92。埋め込みは multilingual-e5-small の int8 で 1 節 20ms

— 10/2 の「埋め込みは選定で倍になる」の裏側。日本語の自分用メモでは語彙検索を捨てないほうが効く、という 24 問の実測。

85store氏（10/2）。メモ約 10 万字を ## 見出し単位に切り、SQLite FTS5（trigram）と multilingual-e5-small（int8、Pi 5 の CPU で 1 節 20ms）を RRF（k=60）で統合し、MCP で引かせる。24 問の自作評価で recall@1／@5 は全文検索 0.71／0.88、意味検索 0.63／0.83、ハイブリッド 0.79／0.92。含意: 小さな日本語コーパスでは全文検索が主、埋め込みは補助。差は 24 問中 1〜2 問なので、自分のメモで測ってから。

試すなら: Python の sqlite3 で CREATE VIRTUAL TABLE notes USING fts5(body, tokenize='trigram') を作り、メモを見出し単位で入れる → 10/2 の要領で質問 20〜30 本を作り、FTS5 だけ／埋め込みだけ／RRF（各順位の 1/(60+順位) の和）の recall@5 を比べる → 3 文字未満の語は trigram で引けないので LIKE で補う（tokenize='trigram' は手元の SQLite 3.45 で動作確認。数字は記事本文、n=24）。

出典: Zenn — Pi 上のメモを、エージェントが節単位で引ける RAG にした（SilverBullet × MCP × ローカル埋め込み）
