Claude Code のキャッシュは 60 分空くと消える — 31,362 リクエストの実測でヒット率は 45〜60 分空きなら 91.7%、60 分を超えると 5.9%。対策は「文脈 70% で切り替え」「長い出力はサブエージェント」「1時間空いたら resume しない」

— 9/6 特集③の「先頭一致」の原理に、自分のログで測った数字がついた。resume するかどうかを時間で決められる。

hanafusay氏（TOKIUM、9/29）。Claude Code のログ 31,362 件を直前からの経過時間で分けると、ヒット率は 45〜60 分で 91.7%、60 分超で 5.9%。Codex CLI では文脈使用率 50%→90% で送信トークンが 2.9 倍、compact で 224,616→52,822。対策は3つ: 使用率 70% で切り替える、テスト実行やログ解析はサブエージェントに渡す、1時間空いたら resume せず新規で始める。含意: サブスクの主会話は TTL 1 時間。休憩は 1 時間以内か、超えたら新規。

試すなら: /usage の「Prompt cache (main)」行でヒット率と直近ミスの原因を見る（v2.1.251 以降、原因表示は v2.1.260 以降） → 1 時間以上空けた大きなセッションは resume せず新規か要約からの再開にする → API キー運用なら settings に "promptCacheTtl": "1h"（TTL の既定＝サブスクの主会話 1 時間・それ以外 5 分、設定名と /usage の行は docs/en/prompt-caching で確認済み。数字は記事本文）。

6GB の RTX 3050 ノートで Qwen3 4B に GUI を操作させる — 画面をスクショでなくアクセシビリティツリーで渡し、475 ノード（170KB）を表示中の 11 要素（1.7KB・約 500 トークン）に絞って「番号を選ぶだけ」にすると、4手 8.6 秒・41 回連続成功

— 9/19・9/28 の「ローカルLLM に判断だけさせる」の続き。4B でも入力を絞って選択式にすれば、手元の GPU で実務の操作が回る。

mappy氏（9/27）。gedit の UI を AT-SPI2（アクセシビリティツリー）で読み、表示中の要素だけを番号つきで渡し、/api/chat の JSON schema で {"choice": <int>} だけ返させる（temperature 0、qwen3:4b-instruct 3.2GB・100% GPU）。1 手目のプロンプトは 381 トークン、判断は 1 回 1 秒弱で、遅いのは LLM 以外。効いた型は「1サブ目標＝1動作」と「達成条件はコードで判定」。含意: 小型モデルは前処理と判定条件で使う。

試すなら: ollama pull qwen3:4b-instruct → 操作対象や状態の一覧を「番号つき・表示中のものだけ」に絞って渡す → /api/chat の format に JSON schema を渡して番号だけ返させ、完了判定は自分のコードで書く（構成・数字・schema は記事本文で確認済み。format の JSON schema は Ollama の structured outputs）。
