auto mode の分類器（許可・拒否を判定するモデル）を CLAUDE_CODE_AUTO_MODE_MODEL で選べる: 既定は Sonnet 5、v2.1.302 以降でフル ID を指定。ただし /status の Auto mode server が Enabled ならサーバー側検査が主で、手元の分類器だけにするには CLAUDE_CODE_AUTO_MODE_SERVER=0（公式 docs/en/permission-modes、11/9 確認）

— 11/6 のぬまーん氏の 111 件ルール、11/7 の denyInsteadOfPrompting と合わせて、auto mode の「誰が判定するか」まで自分で決められる。

公式 docs/en/permission-modes（11/9 確認）。auto mode の分類器は既定で Sonnet 5 が担い、CLAUDE_CODE_AUTO_MODE_MODEL にフル ID を書くと差し替わる（v2.1.302〜）。Opus 5・Sonnet 5.5・Opus 5.5 は指定しても既定に戻る。多くのセッションはサーバー側検査（v2.1.271〜）が先なので、手元の分類器だけにするなら CLAUDE_CODE_AUTO_MODE_SERVER=0。含意: 変えたら debug ログで効いたか見る。

試すなら: ~/.claude/settings.json の env に "CLAUDE_CODE_AUTO_MODE_MODEL": "claude-sonnet-4-6" → claude --permission-mode auto --debug-file classifier-debug.log で起動し curl https://example.com を実行させ、ログの classifier_request_started の model= を確認。違うモデルなら ignoring CLAUDE_CODE_AUTO_MODE_MODEL を検索、行が無ければ /status の Auto mode server を見る（いずれも公式の手順）。提供元が出せないモデルを指定すると検査が失敗して各操作が拒否されるので、まず 1 セッションで試す。

Claude Code 12 セッションで Mac が重い原因は statusLine の npx -y ccstatusline@latest を 10 秒ごとに起動していたこと: 10 秒で約 190 プロセス、npx 1 回は約 23 秒・CPU 1.75 秒で、12 並列÷10 秒＝常時約 2 コア。インストール済みを node で直接呼べば 1.2 秒（もんすん氏、11/9）

— /statusline で入れたまま忘れた statusLine は全セッションで動く。並列運用の固定費は「1 回の費用×並列数÷間隔」で見る。

もんすん氏（11/9）。12 並列で cmux 本体は CPU 約 4% なのに重く、10 秒間に新規プロセス約 190、npx 起動の node が同時 26 本。原因は statusLine の npx -y ccstatusline@latest＋refreshInterval: 10 で、アイドル中も全セッションが 10 秒ごとに起動。1 回あたり経過約 23 秒・CPU 約 1.75 秒、1.75×12÷10≒2.1 コア。対策は statusLine の削除（グローバル導入・間隔延長は未検証）。含意: 繰り返し実行の費用は 1 回×並列数÷間隔。

試すなら: ~/.claude/settings.json の statusLine.command が npx -y …@latest なら、グローバルに入れて実体を直接呼ぶ → refreshInterval は外す（公式 docs/en/statusline: 未設定ならイベント時だけ実行、設定すると N 秒ごとに追加実行、最小 1）→ 並列が多い日は ps -eo etime,comm | grep -c node で起動数を見る。
