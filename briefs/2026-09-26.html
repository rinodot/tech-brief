Anthropic の Claude Code チームが「effort の使い分け」を公開 — 低（1〜2分）で実装、高（11〜33分）で検証、最大（28〜79分）は自律で難問。仕様→低で実装→低で見直し→高で検証のループが推奨の型

— 9/23 の「既定は medium」の続き。いつ上げ下げするかの公式の答えで、/effort を会話の途中で切り替える前提。

claude.dev ブログ（Thariq Shihipar 氏、9/25）。4段階の使い分けは、低＝ループの中で速く返してほしい時（ブレスト、下書き、簡単な変更）、中＝普段の実装、高＝検証やエッジケースが大事な仕事（既存コードのバグ修正）、最大＝難問を完全に自律で解かせる時。例示された所要時間は低 1〜2分、中 4〜22分、高 11〜33分、最大 28〜79分で、対話の途中で /effort を切り替える前提。

著者の型は「仕様を渡し、足りない点を自分に質問させる → 低 effort で実装 → 要点が合っているか低のまま見直し → 高 effort で検証とテスト」。Terminal-Bench 3.0 では effort を低→最大にするとセキュリティ 64→87%、ハードウェア 34→75%（Fable 5.1／Opus 5.5 の例）で、使うトークンの中央値も段階ごとに増える。含意: 既定の medium を固定せず、書く工程は低、確かめる工程は高に振ると、時間と枠を同時に節約できる。

試すなら: /effort low にして仕様の穴を質問させてから実装 → 見直しもそのまま低で → テストと検証だけ /effort high（保存は Enter、9/23 の手順）→ 効果は /usage の減り方と、9/25 の「Claude が読める数値」を1つ決めて前後で比べる（各段階の説明・所要時間・ベンチの数字は記事本文で確認済み）。

出典: claude.dev Blog — Using Claude Code: Spending your effort

Firestore のセキュリティルールを AI にレビューさせたら指摘 58件 — エミュレータで 122 のテストを流して残ったのは 7件、本当に直したのは 3件。「AI の指摘は再現してから直す」パイプラインの実例

— 9/19 の「本番ルールが if true だった」の続き。指摘を検証せずに直していたら、51件分の無駄な修正をしていた。

Iskandar Jajuri氏（9/24）。Firebase アプリ DriveMate のルールを AI にレビューさせ、58件の指摘を probes.cjs（122 のテストケースを firebase emulators:exec で実ルールに投げる）と adjudicate.cjs（指摘と結果を突き合わせる）で検証。再現したのは 7件（約12%）、51件は誤検知。実際に直したのは update の項目制限漏れなど管理者権限が要る 3件。含意: 指摘の採否をエミュレータの結果に任せると、修正は 3件に絞れる。

試すなら: AI の指摘1件につき「入力・現状の判定・あるべき判定」を1テストにして firebase emulators:exec でスクリプトごと流す（記事の構成）→ 再現した指摘だけ直し、直した後も同じテストを回帰に残す（土台は 9/19 の rules-unit-testing と同じ）。

Flutter アプリにローカルLLMを組み込んだら macOS で壁が4つ — flutter_gemma は macOS 非対応の API が多く断念、llama_cpp_dart は dylib をビルド時に Frameworks へ入れて署名しないと Gatekeeper に止められる。日本語は 0.5B の Qwen だと中国語が混ざり TinySwallow-1.5B に

— 完全オフライン・追加費用なしで LLM を Flutter に入れる実例。Android でも「ネイティブ側の組み込みと署名」は同じ論点。

maylab氏（9/24）。flutter_gemma は fromBundled() が macOS 非対応、fromNetwork() も初期化で失敗。llama_cpp_dart の dlopen 拒否は、Podfile の post_install で dylib を Contents/Frameworks/ に入れて署名し解決。Qwen2.5-0.5B は中国語が混ざり TinySwallow-1.5B-Instruct（約1.1GB）へ。含意: 小型は日本語特化の蒸留版を選び、JSON は切れる前提で括弧を補う。

試すなら: まず Dart の CLI スクリプトで llama_cpp_dart と GGUF の読み込みだけ通す（記事の順番）→ macOS なら Podfile の post_install で dylib をコピーして署名、サンドボックスは com.apple.security.network.client を entitlements に → TinySwallow のモデルカードにある「実験的・商用非推奨」の注記を確認してから配布を判断する。

出典: Qiita — FlutterアプリにローカルLLMを組み込む中で立ちはだかった壁
