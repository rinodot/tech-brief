無人の claude -p は、ツールの許可がなくて何もしなかった回でも終了コード 0・is_error false・subtype success のまま。25 回の起動（14 回はモデル実行、合計約 $0.023）で 1 になるのは引数の誤り・認証なし・存在しないモデル・--max-turns・--max-budget-usd だけ。拒否を見つける手がかりは --output-format json の permission_denials と成果物の有無（yorusuzu 氏、10/18）

— cron や CI の claude -p を「exit 0 なら成功」で見ていると、権限不足で何もしなかった回を成功に数える。昨日の deny／フックの話の裏側。

yorusuzu 氏（10/18）。Windows・haiku で 25 回起動して表にした。終了コード 1 は引数の誤り、認証なし、--max-turns・--max-budget-usd の超過。許可なしで Write を頼んだ回（default・dontAsk とも）は 0・false・success で、permission_denials 1 件とファイル未作成だけが手がかり。既定の text 形式ではそれも見えない。含意: 終了コードは「claude が正常に終わったか」、仕事が済んだかは成果物で見る。各条件 1〜3 回。

試すなら: 無人実行は必ず --output-format json（か stream-json）にし、終了コード → is_error／subtype → permission_denials の件数 → 成果物（ファイル・PR）の順で判定する → シェルは set -o pipefail（パイプで終了コードが隠れる）→ 拒否が出たら許可を「検証の経路ごと」に足す（tekuteku 氏、10/18: launchd の claude -p に Bash(go test:*) を許可してもテスト用ファイルを書く Edit(verify/**) が無ければテストは一度も走らず、終了コードは 0。拒否は stream-json の最終 result に permission_denials として並ぶ。--permission-prompts none で無人実行の拒否を明示、Write(path) のルールは参照されない）。

出典: Zenn — claude -p の失敗は終了コードで分かるか: is_error・subtype・permission_denials を条件別に実測
