スキルは「候補に選ばれる」と「実際に読まれる」の 2 段階で発火する: 説明文だけを見せる一覧テストでは 9/9 で選ばれるスキルが、実作業のセッションでは 0/2 で読まれず、description に「比較対象を開く前に読め」と足しても 0/2。UserPromptSubmit hook で依頼文に「棲み分け｜整理｜統合…」の動詞を見つけたら additionalContext で名指しすると 2/2 で先に読んだ（Codex も 2/2）。節目ごとに hook から選び直させる別の実測では読まれる率 45%→83%（pacy 氏・こかげ氏、10/25）

— 自作スキルが「入れたのに使われない」原因を、description の書き方ではなく発火の段階で切り分けた。hook で名指しする型は読者の Skills 運用にそのまま入る。

pacy 氏（10/25）。Claude Code と Codex 共用の dotfiles、4 スキルで測定。説明文だけ見せて選ばせる一覧テストでは skill-restructuring が 9/9 で選ばれるのに、実際に「Linear 証跡と GIF 録画の 2 スキルを棲み分けたい」と頼むと、その 2 つを直接開いて 0/2 で読まれない。description に「比較対象を開く前に読め」と足しても 0/2。選ぶ段と読む段は別で、説明文は後段に効かない。

効いたのは UserPromptSubmit hook。依頼文に /棲み分け|整理|統合|分割|改名|分け方|重複/ が当たり、かつ skill という語かスキル名があれば、additionalContext で「比較対象を開く前に skill-restructuring を読んで使え」と英語 1 文を添える。これで 2/2 先に読み、Codex でも 2/2。スキル同士の参照は「届ける側が作る側を名指しする」一方向に限る。各条件 2〜3 回の現象報告。こかげ氏（10/25）も、コード→文書→検証→リリースの節目で hook から選び直させると読まれる率 17/38（45%）→52/63（83%）と報告。

試すなら: 使われないスキルがあるなら、まず「候補になるスキルを挙げて」と一覧で聞き、選ばれるのに実作業で読まれないのかを切り分ける → 読まれない側なら ~/.claude/settings.json の hooks.UserPromptSubmit に node skill-reminder.mjs を登録し、stdin の JSON の prompt に正規表現が当たった時だけ {"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"Load and use the ＜skill 名＞ skill now, before …"}} を標準出力に返す（公式 docs/en/hooks: UserPromptSubmit は依頼文を置き換えられず additionalContext を添えるだけ。exit 0 の素の stdout も文脈として渡る）→ 誤発火が出たら当たる語を絞る。

Claude Code のプロンプトキャッシュは、サブスクなら保持 1 時間（30・50・55・58 分後は読めて 61 分以降は外れた）。期限切れ後の 1 ターンは読めた時の 11 倍の費用、65 分空けた書き直しは $0.175、先に /compact してあれば $0.032。先頭を変えない（日時を書かない、途中でモデルや MCP を変えない）が基本で、公式 docs は保持を promptCacheTtl（5m/1h）で選べると明記（songchong 氏 10/26）

— 休憩明けの 1 ターンが遅くて高い理由がこれ。claude -p の自動化は API 課金で保持 5 分なので、1 時間にしたいなら設定が要る。

songchong 氏（10/26）。サブスクの Claude Code＋Sonnet 5.5 で再開間隔を変えると、30〜58 分は読めて 61 分以降は外れた。2 ターン目は 53,801 トークン中 49,997 が読み、3,802 が書き込みで、費用の 75% は書き込み側。先頭の日時行で 10,774、MCP 1 個追加で 3,786、モデル切替で 12,764 トークンが書き直しになる。公式 docs: 保持はサブスクの本会話 1 時間、API キーと usage credits は 5 分で、promptCacheTtl（5m/1h）で選べる。

試すなら: /usage の「Prompt cache (main)」で命中率と warm かを見る（v2.1.251 以降。最後のミスの推定原因は v2.1.260 以降）→ 1 時間を超えて離れる前に区切りで /compact（公式 docs: 冷えてからの compact は全履歴を非キャッシュで読み直すので最も高い）→ claude -p や API キー運用は ~/.claude/settings.json に "promptCacheTtl": "1h"（または CLAUDE_CODE_PROMPT_CACHE_TTL=1h）、確認は claude -p "hello" --output-format json の usage.cache_creation.ephemeral_1h_input_tokens → セッション中はモデル・MCP を変えない（effort の変更は Opus／Sonnet／Haiku 5.5 と Fable 5.1 ならキャッシュ維持）。

— ローカル LLM で RAG を組む読者には「310M の日本語リランカーで API 版と同じ 90%」が要点。CPU で 7.8 秒なら GPU に載せる価値がある。
