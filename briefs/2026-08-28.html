Google Playのメモリ閾値が判明 — 4GB機ならアプリ2GBまで

— 昨日「MB値はサポートページ送り」と書いた件の続き。自分のアプリで測れる数字になった。

判定はAnonymous RSS+Swapの90パーセンタイル・フォアグラウンド状態で、端末のRAM容量ごとに上限が決まる。4GB機ではアプリ2GB／ゲーム2.25GB、6GB機で2.25／2.75GB、8GB機で2.25／3.5GB、12GB機で3.25／4GB、16GB機で4.25／5GBだ。ビットマップは別枠で、ユーザーが見ている状態とバックグラウンドで200MB超、キャッシュ状態で400MB超が超過扱いになる。DEXコードは、アプリでDEXが10MB超、ゲームで50MB超の場合に、難読化・最適化・縮小のそれぞれで最低25%のカバレッジが要る。超過するとアプリは動作を遅くされ、終了されることがあり、Play Console上での露出と公開能力も落とされる。施行は2027年2月。

Zero-Tap Sign-Inのほうは対象がAndroid 9以降のモバイルとタブレットで、2027年4月施行。含意: 画像を多く扱うFlutterアプリなら、まずビットマップの200MB／400MBを実測しておきたい。DartのGCとimage cacheの設定が効く場所だ。

出典: Google Play ヘルプ

Claude Code v2.1.247の中身が公開 — API費用の最適化コマンドが入った

— フックのエラー処理を雑に書いていた人が救われる修正が入っている。

45項目超の回で、目を引くのは/claude-api cost-optimizeだ。既存プロジェクトのAPI利用を走査し、キャッシュ・バッチ・effortの観点から節約案を出す。ほかに、サブエージェントが最初の404で親にフォールバックする不具合と、フックが大量のエラーを吐くとセッションが「Prompt is too long」で固まる不具合を修正。Sonnet 5の自動コンパクトが100万トークン枠の全体（約967K）を使うようになった。含意: 自動化を増やすほどフック起因の停止は起きやすい。

出典: Claude Code changelog

Debianの投票は公式ページ上では今日締切 — 「1週間延長」報道の裏が取れない

— 8/16に取り上げた件の決着日。ただし日程そのものが不確かになっている。

「LLM生成コードをどう扱うか」の一般決議は、公式ページ上では今日8/28 23:59 UTCが締切だ。ただしThe Registerが8/26に「DPLが1週間延長した」と報じており、裏が取れない。公式ページは8/14以降ビルドされておらず、メーリングリストはボット対策で読めず、他媒体の追随報道もない。集計ページは投票383件・有効279件・投票者271人で、進行中であることだけを示す。全8案＋棄権のうち、全面禁止のA案だけが3:1の特別多数を要する。
