v2.1.318（11/4）で claude auth status にログインの失効日時 loginExpiresAt、claude -p の JSON 結果に credential_expires_at が付いた。Clopy 氏（11/5）の実測: auth status は 183 ms・exit 0・課金なし、-p --output-format json は同じ値を返すが $0.078・1,930 ms、素の -p には失効の手掛かりが出ない（stderr 0 文字）。cron の前に「残り 3 日で止める」1 行チェックに

— 無人の claude -p が黙って Not logged in で死ぬ前に、無料の 0.2 秒で先に気づける。定期便の先頭に足す価値がある。

Claude Code v2.1.318（11/4）。claude.ai ログインの有効期限が claude auth status の loginExpiresAt と claude -p --output-format json の credential_expires_at に出るようになった。Clopy 氏（11/5）の実測は auth status が 183 ms・exit 0・課金なし、JSON 付きの -p は同じ値を返すが $0.078・1,930 ms、素の -p は stdout 5 文字・stderr 0 文字で手掛かりなし（10 日前の警告は未再現）。

型は 3 行: cron 本体の前に auth status を無料で読む、すでに JSON で -p を呼ぶ CI は結果を流用、素の -p に頼る設計は不可。残日数が THRESHOLD_DAYS=3 を切ったら exit 1。落とし穴は BSD date で末尾 Z を落とすと JST 解釈で 32,400 秒ずれたこと。同じ版の無人向け変更: 変化がなければ ~/.claude.json を書き直さない、壊れた ~/.claude.json は上書きせず起動失敗、サブエージェントは 3 分超のシェルを後ろへ回してキャッシュを守る。

試すなら: 定期便の先頭に claude auth status（JSON の loginExpiresAt）を置き、date -u -d "$EXP" +%s との差が 3 日未満なら exit 1（macOS の BSD date は TZ=UTC を明示）→ すでに claude -p … --output-format json を呼ぶジョブは credential_expires_at を読むだけでよい → 失効したら claude auth login か claude setup-token（changelog の失敗メッセージが案内する 2 つ）。API キー認証と --bare は著者未検証。

メインを Sonnet にして難所だけ Opus に相談させる advisorModel（公式の advisor tool）と、下働きを Haiku にする CLAUDE_CODE_SUBAGENT_MODEL の 3 行設定を実測: Sonnet 単独 $0.29・29 秒・テスト 18 件 OK、advisor あり $0.98・85 秒・18 件、Opus 単独 $1.01・83 秒・21 件。Explore は model: inherit なので Sonnet のまま（wfukatsu 氏 11/5、2.1.317・各 1 回）

— 昨日の「上流だけ強いモデル」を 1 セッションの中でやる公式の仕組み。ただし advisor は毎回会話全体を読み直すので、短い作業では Opus 単独と同じ費用になる。

wfukatsu 氏（11/5）。settings に "model": "sonnet"・"advisorModel": "opus"・env に CLAUDE_CODE_SUBAGENT_MODEL=haiku を置き、3 条件を各 1 回。Sonnet は指示しない限り advisor を呼ばず、「相談せよ」と書くと 2 回呼んで $0.98、advisor への入力は約 6.3 万・7.3 万トークンでキャッシュ 0。公式 docs も「advisor は毎回会話全体を読み、cache されない」「Anthropic API のみ・実験的」。

試すなら: ~/.claude/settings.json に {"model": "sonnet", "advisorModel": "opus", "env": {"CLAUDE_CODE_SUBAGENT_MODEL": "haiku"}}、1 回だけなら claude --advisor opus、対話中は /advisor opus／/advisor off（公式 docs/en/advisor 11/5 確認。v2.1.260〜は -p でも /advisor が使え、無効化は CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1）→ 長い作業の依頼文に「方針を決める前と完了宣言の前に advisor に相談」と書く → Explore も Haiku にするなら CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1（自作エージェントの model: opus も Haiku になる）。

— 1 件目と 2 件目は Firebase Auth＋Google サインインを使う Flutter アプリなら同じ形で潜む。「テストで開かれない UI をどう開くか」の実例。

Stylianidis 氏（11/4）。家計簿アプリ（Flutter・Firebase・15 言語・テスト 1,100 本超）を実機で 6 分。原因は、StreamBuilder に authStateChanges() を毎 build で渡し再ビルドごとに「待機中」から始まって入力が消える、リソース縮小が文字列リソースを未使用扱いで削除しデバッグでは出ない、日曜限定ダイアログがテストで開かれない、isEmpty ? 'a' : 'b' の文字列が翻訳キー検査をすり抜ける。各件にテストを足し、戻すと失敗することを確認。

試すなら: 認証ストリームは late final _auth = FirebaseAuth.instance.authStateChanges(); を State に持ち StreamBuilder<User?>(stream: _auth, …) に渡す（記事のコード）→ Google サインインは server client id を明示して渡し、Firebase 設定ファイルと一致するテストを足す → 条件付き UI（曜日・初回のみ）はテストから強制的に開く入口を作り、320dp×大きめ文字でレイアウトテスト → flutter build apk --release を実機に入れて 6 分触る。
