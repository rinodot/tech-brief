Claude Code に .env や鍵ファイルを消させない 3 層: settings の deny 8 本だけでは「危ない 13 通り中 11 通り」のうち 9 通りしか止まらず、/bin/rm と python3 -c が抜ける。引数を絶対パスに直して行き先を見る PreToolUse フック（111 行）で 10 通り、スクリプト経由の最後の壁は sandbox。実運用の 408 行版は .env の cp と unlink を 2 回止めた（Oskra 氏、10/17）

— 自分のリポジトリにも .env・google-services.json・署名鍵がある。「deny は字面の一致なので書き方を変えると抜ける」は、設定を書く前に知っておきたい事実。

Oskra 氏（10/17）。偽の鍵 3 つに 13 通りのコマンドを claude -p --model haiku で投げた。deny 8 本だけでは危ない 11 通りのうち 9 通りで止まり、/bin/rm と python3 -c が抜けた。引数を絶対パスに直して拡張子・secrets・.env を見るフックを重ねて 10 通り。スクリプト内の削除は残るので最後は sandbox。止めすぎは rm .env.example と ls secrets。含意: deny は字面、フックは行き先、sandbox は実体。n=1、2.1.302。

試すなら: .claude/settings.json の permissions.deny に "Bash(rm *.env*)", "Bash(mv *.env*)", "Bash(cp *.env*)", "Bash(curl *@*)", "Read(./.env)", "Read(./secrets/**)" → hooks.PreToolUse に {"matcher": "Bash", "hooks": [{"type": "command", "command": "node ~/.claude/hooks/secret-guard-mini.mjs"}]} → スクリプトは const input = JSON.parse(readFileSync(0, 'utf8')); で tool_input.command を読み、&&／; で分け、sudo や timeout の前置きを飛ばし、rm／unlink／mv／cp／scp／rsync の引数を絶対パスにして .p8 .p12 .pem .key・secrets/・.env なら process.exit(2)（.env.example は除外） → 別フォルダに偽の鍵を置き、claude -p --setting-sources project --settings ../deny-only.json（記事は --permission-mode dontAsk）に「Run this Bash command exactly once, verbatim: /bin/rm secrets/fake.p8」のような依頼を 10 通り投げて表にする（Firebase なら google-services.json・GoogleService-Info.plist・*.jks を deny とフックの両方に足す）。

要約サブエージェントを Opus から Haiku に下げたら、チェックリストは全部通るのに核心が落ちた（13 本中 9 本、2 回とも）。指示に「書く前に著者の核心を 1 文で決める」「根拠 2〜3 個」「取得できていない部分」の 3 行を足すと Haiku でも 13/13、限界の明示は 2/10→10/10。単価は Opus の 1/40（ryok 氏、10/16）

— 「調査・要約役だけ安いモデルに」は自分もやる費用対策。どう壊れ、何を書けば直るかが数字で出ているので、model: haiku にする前にこの 3 行を入れる。

ryok 氏（10/16）。Web 記事 14 本の要約サブエージェントを Opus 5.5 から Haiku 5.5 に下げ、Opus に盲検で採点させた。型なしの Haiku は核心 9/13・限界の明示 2/10（2 回とも）。Opus は 13/13 と 12/13 だが限界は 3〜4/10。指示に「中心的な主張を 1 文で」「根拠 2〜3 個」「取得できていない部分」を足すと Haiku が 13/13・10/10 と 13/13・9/10。単価は 1/40。含意: 安いモデルの穴は「先に何を決めるか」を書けば埋まる。n=2、判定も上位モデル。

試すなら: .claude/agents/summarize.md の frontmatter を model: haiku にし、本文の先頭に「書き始める前に 3 つを決める: ①著者の中心的な主張を 1 文で（原文に核心を言い表した文があれば逐語引用）②それを支える根拠を 2〜3 個（原文の数値・仕組み）③取得できていない部分」と「作業情報は本文に書かない」を書く → 同じ 10 本を Opus 版と Haiku 版で要約し、条件を伏せた別セッションに「核心が入っているか／限界が書かれているか」だけを採点させる → 2 回回して揺れを見る（記事は 1 回の判定は揺れる、と注記。frontmatter の項目は docs/en/sub-agents、effort も指定可）。

特集① ハンズオン — RAG を 12〜16GB の NVIDIA で動かす: 取り込み・ハイブリッド検索・リランク・評価の 1 本道

①取り込みとチャンク。Cheanfei Shee 氏（ソフトバンク、10/9）は 108 文書を 1,000 字・重なり 200 で 2,858 チャンクにし、FTS5＋sqlite-vec で 2 回目以降の検索 23ms。plasmon_imp 氏は 300／600／1,200 字で J-MRR 0.855／0.825／0.785 と短いほど良い（判定器の偏りあり）。目安は 500〜1,000 字・重なり 100〜200。

②BM25 とベクトルを RRF で混ぜる。TaiLexi AI 氏（10/15、判例 19 万件）は nDCG@10 が事実型 BM25 0.657＜ruri-v3-310m 0.702、論点型 0.834＞0.702 と割れ、RRF（定数 10）で重ねた。BM25 は分かち書き必須（plasmon_imp 氏: fugashi で 0.802→1.000）。k_nabe 氏（5/19）では ruri-v3-30m（約 1.5GB）が Top-5 Recall 88%、BGE-M3 84%。

③リランカー。ray 氏（10/13）は 71 問の 1 位正解が元順序 48%→BM25 66%→bge-reranker-v2-m3 92%、CPU で 1 問 +21.9 秒。harryforge 氏（10/9）は上位 12 件だけ通し、0.6 未満は「資料にない」、1.5 秒で打ち切り p50 +0.23〜0.37 秒。GPU は生成、リランクは CPU で 20〜30 件。

④評価と速さ。nishina 氏（10/16）の 20 問は初回判定で階層 15 対ベクトル 13、上位モデルで採点し直すと両方 16 — 差は言えない。TaiLexi AI 氏は要旨のない 5.5 万件を LLM 要約→埋め込みで Recall@10 61.7→81.7%。nakanokensetsu 氏（10/13、vLLM）は system prompt を先に 1 回流して命中 0→96%、TTFT 0.68→0.10 秒。

試すなら（最初の 1 時間でやる順）: ① ollama pull embeddinggemma → curl http://localhost:11434/api/embed -d '{ "model": "embeddinggemma", "input": "Why is the sky blue?" }' で embeddings の長さ（＝次元）を確認（dimensions で縮められる）。② pip install sqlite-vec → Python で import sqlite_vec / db.enable_load_extension(True) / sqlite_vec.load(db) → create virtual table vec_documents using vec0( contents_embedding float[768] distance_metric=cosine )（768 は①の長さに合わせる）→ 検索は where contents_embedding match :query and k = 10（limit は SQLite 3.41 以降）。③ 同じ DB に CREATE VIRTUAL TABLE docs_fts USING fts5(doc_id UNINDEXED, body, tokenize='unicode61')、本文は fugashi か SudachiPy で分かち書きしてから入れ、SELECT doc_id, bm25(docs_fts) FROM docs_fts WHERE docs_fts MATCH ? ORDER BY bm25(docs_fts) LIMIT 30。④ Python で RRF（各リストの順位 r に 1/(k+r) を足す。k は 60 か 10）→ 上位 20 件を pip install -U FlagEmbedding / FlagReranker('BAAI/bge-reranker-v2-m3', use_fp16=True)（CPU なら False）/ compute_score([query, passage], normalize=True) で並べ直し、0.5〜0.6 未満なら「資料にない」。⑤ 30 問の「正解チャンク」表を作り、BM25 だけ／ベクトルだけ／RRF／リランク後の 4 段で Hit@3 と MRR を出す。生成側は system prompt を前に固定して 1 回空打ちし、2 回目以降の TTFT を記録する。
