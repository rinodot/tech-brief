Flutter 3.50（Dart 3.14）。新規プロジェクトは material_ui／cupertino_ui が既定になり、package:flutter/material.dart と flutter_localizations のデリゲートは正式に非推奨（dart fix --apply --code=migrate_design_widgets で移行）。Android は AGP 9.3.1・Gradle 9.5.0・minSdk 24・target 36、FFIgen／JNIgen が安定版、iOS は入力遅延 1 フレーム短縮。pub パッケージに skills/ を同梱して dart run skills@ get で配れる（Flutter 公式ブログ 11/11）

— 次の flutter upgrade で import の非推奨警告と Gradle の前提が変わる。エージェント向けの skills と MCP 設定が公式の配布経路に乗った。

公式ブログ（11/11）。Flutter 3.50 は Dart 3.14 と同時。新規プロジェクトは package:material_ui が既定で、package:flutter/material.dart・cupertino.dart と flutter_localizations のデリゲートは正式に非推奨。Android は AGP 9.3.1・Gradle 9.5.0・KGP 2.4.20・Java 17 以上、minSdk 24・compile／target 36。HCPP は API 34 以上＋Vulkan 端末だけ。

Direct native interop（FFIgen・JNIgen）が安定版。iOS はタッチ入力の遅延が 1 フレーム短縮（60Hz で 16ms）、CocoaPods は縮小して SPM へ。Wasm は JS の 2 倍超、CanvasKit 5.46→3.75MB。公式エージェントプラグインは skills・MCP 設定・flutter-hot-reload ルール同梱、パッケージの skills/ を pub.dev から配れる。含意: import は fix 1 コマンド、Gradle は手動。

試すなら: flutter upgrade（docs の release notes 一覧は 11/12 朝も「3.50.0 (Tentative)」表記なので、stable に来たかは upgrade の結果で確認）→ dart fix --apply --code=migrate_design_widgets（import とローカライズのデリゲートを置換）→ android/ の AGP・Gradle・KGP を新規プロジェクトの既定（9.3.1／9.5.0／2.4.20、Java 17）と見比べる → platform view を使う画面があれば flutter config --enable-hcpp（API 34 未満や Vulkan 以外の端末は従来の platform view に自動で戻る）→ 依存パッケージの skills は dart run skills@ get、自作パッケージは package:skills_lint を CI で → Web なら flutter build web --wasm。release ビルドは外部 Intent の route・dart_entrypoint・cached_engine_id を無視するようになった点も確認。

RTX 3060 12GB で VRAM に載らない Nemotron 3.5 を本体 RAM に逃がして実測。Lightning 30B-A3B（IQ4_XS 17.6GiB）は VRAM 約 9.7GiB で 32〜34 tok/s・128k まで実用、Bolt 74B-A9B（IQ2_XXS 20.5GiB）は 14〜15 tok/s。全部 VRAM に載る Qwen3.8-27B は 20〜21 tok/s・32k まで、Bonsai 2 27B は 31〜33 tok/s・64k まで。11.8 万トークンの読み込みは Lightning 約 4 分（BpF 氏 11/11）

— 自分の 12GB でも MoE なら VRAM 超えのモデルが実用速度で動く。基準モデルを毎回測り直す「物差し」の作りも真似できる。

BpF 氏（11/11）。RTX 3060 12GB・WSL2（RAM 25GB）。生成は短い／約 4k／約 16k 入力の範囲で Lightning 32〜34 tok/s、Bolt 14〜15、Qwen3.8 20〜21、Bonsai 2 31〜33。11.8 万トークンの読み込みは Lightning 約 4 分（以後 28.2 tok/s）、Bolt 約 6 分半。日本語 500 字の返事までは Bonsai 2 が 33.7 秒で最短、Lightning は 93.0 秒。著者の既定は Bonsai 2、長文読みは Lightning。各問 1 回。

試すなら: WSL2 の RAM 割り当てを先に増やす（記事は CPU 4 コア・25GB）→ ./llama-server -m NVIDIA-Nemotron-3.5-Lightning-30B-A3B-IQ4_XS.gguf --jinja --host 127.0.0.1 -c 131072 --parallel 1（記事のコマンド。VRAM に載らない専門家の重みは --fit で本体 RAM に置く前提、本家 llama.cpp e14a779）→ 基準は ./llama-server -m Qwen3.8-27B-UD-Q2_K_XL.gguf --jinja --chat-template-kwargs '{"reasoning_effort":"medium"}' -ngl 99 -c 32768 --parallel 1 → 物差しは「基準モデルを毎回測り直す」「日本語 500 字の返事が出終わるまでの秒数」「生成 10 tok/s を実用の下限」の 3 つを自分の問題で固定 → Bonsai 2 だけは PrismML 版 llama.cpp。

GitHub CLI v2.99.0 の --attach で、Claude Code が作る PR に変更前後のスクリーンショットを貼らせる。gh pr create --body-file pr-body.md --attach ./before.png --attach ./after.png の 1 コマンドで最大 50 ファイル、本文中の相対パスはアップロード後の URL に書き換わる。CLAUDE.md は「UI 変更はスクショを撮って添付」「画像はリポジトリ外に保存」「本文は一時ファイル」の 3 行（つけ麺テキーラ氏 11/11）

— Flutter の UI 変更 PR を自分で動かして確かめる手間が減る。gh の新機能を Claude Code の約束事に落とす例。

つけ麺テキーラ氏（11/11）。GitHub CLI v2.99.0 の --attach は画像・動画を上げ、本文中の同じパスを URL に置換する（公式リリースノート）。pr create／pr edit／pr comment で使え、1 回 50 ファイルまで、Enterprise Server は不可。CLAUDE.md には「UI 変更は前後のスクリーンショットを PR に添付」「画像はリポジトリ外に保存」「本文は一時ファイルに書き --body-file と --attach で作る」の 3 行。一部の失敗でも PR は作られる。

試すなら: gh --version で 2.99.0 以上（2026-09-01 公開）→ CLAUDE.md に上の 3 行 → Flutter なら撮影手段を flutter screenshot --out=/tmp/shots/after.png（接続中の端末を撮る公式コマンド）と指示 → gh pr create --title … --body-file /tmp/pr-body.md --attach /tmp/shots/before.png --attach '/tmp/shots/after.png#修正後'（# の後ろが alt テキスト、公式例）→ 一部失敗でも PR は作られるので「失敗したら gh pr edit ＜番号＞ --attach で追加、gh pr create は繰り返さない」と書く。v2.99.0 はコーディングエージェントから呼ばれるとスピナーを文字だけにする変更も入った。
