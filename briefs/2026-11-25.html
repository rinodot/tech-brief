会議の発言が「調べ物か」を、手元の小さなモデルが確率で即答する。meeting-scout の判定役の器に、そのまま入る形

Liquid AI の d1-2B（10/24 公開・1 か月前）。文章を作らず、型の決まった問いに 1 回の計算で確率を返す。今夜は道具が古く、安全審査でも止まり、動かせなかった

1はじめ: Mac 内蔵のモデルは「はい」と書くだけ。確からしさが返らないREADME:「確率が返らないので閾値でも切れない」
2いま: 30B の大きなモデルに、答えの 1 文字目の確率を聞いている判定役（judge）は、確率を返すモデルに差し替える器として残してある
3d1: 問いの札を渡すと、文章を書かずに目盛りで答える札の型（noul・choice・score）が、判定役の器と同じ。0.92 は絵のための例
  • meeting-scout の README（judge の節）:「I/F は TypeSafe AI の Jev（POST /v1/systemone）に寄せてある」「Jev のキーが取れたら差し替えるだけで本物の確率に乗り換えられる」
  • d1 を llama.cpp で動かすと、同じ /v1/systemone で state と型付きの問いを受ける（モデルカード）。d1 のモデルカードは Jev の判定ベンチ（Decision Index・JevBench）で成績を出している

器の問いと、d1 が受ける形を並べた

meeting-scout の judge/questions.default.json（型だけ）
1new_topic noul 調べる論点が新しく出たか
2owner choice 誰が調べるか
3enough_context noul 今すぐ調べ始められるか
4kind choice 調査の種類
5query text 調べるべき問いを 1 文でまだ
d1-2B（llama.cpp）が受ける形
POST /v1/systemone
受ける　state ＋ noul・choice・score
まだ　抜き出し（text）・複数選択
1〜4 はそのまま渡せる形。5 は今の仕組みに残す

問いを増やしても、ほとんど遅くならない（モデルカードの数字）

  • モデルカードの値（Apple M5 Pro・bf16・コンパイル後の 20 回の中央値）。手元では測っていない
  • meeting-scout の README の実測（M4 Pro）は、Mac 内蔵のモデルが問い 1 つで 634ms・5 つで 1245ms、qwen3:30b の確率のゲートが中央 0.3 秒。機械も条件も違うので、並べて比べてはいない
  • 話題: Zenn の gemcook（Sho Uemura 氏・11/20）が d1-2B の MLX 版で Web カメラの表情を 5 択の確率にし、Mac で 1 回 0.1 秒前後・メモリ約 5GB と書いている

今夜、動かせなかった理由

mlx-vlm は安全審査で止めた0.8.1 は Claude ok / Codex ng。モデルの配布元が指す Python をそのまま実行する経路、待ち受けが既定で 0.0.0.0 など
llama.cpp が古い手元は 0.5.0。d1 は v0.8.0 以上が要る。brew には 1.0.0 がある（上げるのは本人の判断）
ライセンスに年商の線LFM Open License v1.0。商用は年商 1,000 万ドル未満なら使える。日本語の会議での当たりは未確認

始めるなら

1llama.cpp を v0.8.0 以上に上げる
2llama-server -hf LiquidAI/d1-2B-GGUF:Q8_0 -b 8192 -ub 8192（重み 1.8GB）
3eval/local.mjs と同じ発話を流し、qwen3:30b と当たり・速さを並べる
▶ これを始めるmeeting-scout の判定役に d1 を当てて、qwen3:30b と比べる
送ると確認画面が開き、▶ を押すと Mac の Orca でセッションが始まる
