Firebase に「サービス単位の支出上限」が付いた — AI Logic／Cloud Functions／App Hosting は月額を決めておくと 100% で自動停止する

— 個人開発で一番怖い「バグや急増で数万円の請求」に、Functions と Gemini API の分だけでも蓋ができる。

Firebase 公式ブログ（9/14、Yvonne Monterroso氏）。プロジェクトごと・サービスごとに月額の上限を置くと、50%・80% でメール、100% でそのサービスの新規利用が月末まで止まる。対象は AI Logic（Gemini API）、Cloud Functions、App Hosting、Extensions。設定は Firebase コンソールの 設定 → Usage and billing → Details & settings の Service-level spend caps。解除は同じ場所の Lift、再開まで最大1時間。

注意は2つ。①ハードキャップではない。集計の遅れで停止まで数分かかり、その間の超過分は請求される（公式は「許せる額より少し低く」）。②裏の API 単位で効き、Cloud Functions の上限は Extensions の関数にも、Gemini API の上限は Genkit や ADK からの利用にもかかる。含意: Firestore・Storage・Auth は対象外。Cloud Functions と AI Logic に月額を置き、Firestore は従来の通知だけの予算で見る二段構え。

試すなら: Blaze のプロジェクトで Firebase コンソール → 設定 → Usage and billing → Details & settings → Service-level spend caps で Cloud Functions に「許せる上限より少し低い月額」を Configure。50%・80% のメールが自分に届く宛先（請求管理者かプロジェクトオーナー）かも確認する。

出典: The Firebase Blog — Introducing Firebase spend caps

llama.cpp の -ngl は「多いほど速い」ではない — RTX 4070 12GB で Qwen3.8-27B を8点測ると、42→44 層でプロンプト処理が 19 分の 1 に落ちた

— 12〜16GB の GPU で 27B を動かすなら、層数は表で決めずに自分で崖を測るしかない。

ローカルAIラボ（9/3、9/9更新）。Qwen3.8-27B-Q4_K_M を llama-bench で -ngl 8点。プロンプト処理は 40 層 341.32 tok/s、42 層 318.66、44 層で 16.51 に急落、全層でも 27.30。生成は 42 層の 3.00 tok/s が最速。VRAM は 40 層以上どれも 11.8GB 前後で崖が見えない。仕組みは筆者も未特定（あふれた分のメモリ退避が私の読み）。含意: 生成はベンチと実機で一致、プロンプト処理は5倍遅かったとも。ベンチで当たりを付け、実際の -c で測り直す。

試すなら: llama-bench -m Qwen3.8-27B-Q4_K_M.gguf -ngl 36-48+2 -p 512 -n 128（範囲指定は公式 README の書式）。pp が急落する直前の層数で llama-server -ngl 42 -c 32768 -fa on を立て、実際の長さで測り直す。

出典: Zenn — llama.cppの -ngl には崖がある：RTX 4070 12GBで27Bを8点実測

机の Claude Code を「サーバー」にしておくと、スマホから開いたセッションごとに別の worktree が切られる — claude remote-control --spawn worktree

— このブリーフを読んでいるスマホから、そのまま自宅 PC の Claude Code に仕事を投げられる。

公式 Remote Control のサーバーモード。claude remote-control を走らせると、実行も MCP も PC 側のまま、Claude アプリの Code タブから指示と承認ができる。--spawn worktree を付けると、スマホから開くセッションごとに git worktree が切られ、同じファイルを取り合わない。受信ポートは開かないが、転写は Anthropic 側に残る。Pro/Max 以上。含意: ワークフローの進捗も同期されるので、ultracode を PC で走らせ外から見られる。

試すなら: リポジトリで claude remote-control --spawn worktree --name "myapp" → スペースキーで QR を出してスマホの Claude アプリで読む → Code タブから新規セッションを2つ開き、git worktree list で別ディレクトリになっているのを確認。

出典: Claude Code Docs — Continue local sessions from any device with Remote Control
