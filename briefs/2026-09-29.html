Claude Code の /claude-api hillclimb が「直したら本当に良くなったか」を評価で回す — 社内サポート 44 件で Opus 4.8 の 74.4%・1件 4.6 セントが、プロンプト監査と Sonnet 5 で 98.9%・1 セントに。未見の 14 件でも 78.6%→90.5%、費用は約 1/5（公式 9/28）

— 9/27 の prompt-audit は「古い書き方を見つける」まで。その先の「削って良くなったか」を測る型が同じ同梱スキルに入っていて、自作 Skill や CLAUDE.md にも向けられる。

Lance Martin氏（Anthropic、9/28）。/claude-api build-eval は対話で評価セット（ケース・採点器・実行器・1件ごとの記録・スコア一覧）を作る。/claude-api hillclimb は評価を train／test に無作為に分け、1ラウンド1変更を提案する。両方上がれば採用、train だけ上がれば過学習として戻し、2〜3ラウンド止まれば test 最良版を信頼区間つきで報告する。変える対象はシステムプロンプト・Skills・ツール説明・モデルと effort・ハーネスのコード。

実例は 44 件（探索 30・未見 14）。Opus 4.8（high）74.4%・4.6 セント → 儀式的なツール呼び出しや矛盾ルールを削り Opus 5.5 low で 87.8%・1.9 セント → Sonnet 5 low で 88.9%・1 セント → ルーティング規則と返金上限の相互参照を足して 98.9%。未見の 14 件は 78.6%→90.5%、費用約 1/5。同じ手で claude-api Skill 自体も 66%→約 88%。含意: 削る・安いモデルに替える・規則を足す、を測ってから採れる。

試すなら: 自作 Skill か CLAUDE.md で結果が揺れる作業を1つ選び /claude-api build-eval で評価セットを作る → /claude-api hillclimb に目標（精度か、精度維持で費用減か）を答える → 提案 diff は test が上がったものだけ採用する（両サブコマンドは v2.1.259 以降、評価の実行は対象アプリの API 呼び出し分が従量。コマンド名と版は docs/en/commands、数字と手順は記事本文で確認済み）。

出典: claude.dev — Automating eval design and hillclimbing with Claude

9/28 のリリース。sonnet エイリアスは Sonnet 5.5 を指し、API 価格は Opus 5.5 の半額、既定 effort は medium、thinking は切れず fast mode もない。/mcp reconnect all は接続失敗・要認証の MCP を一括で再試行し、Ultracode は /effort の独立トグルになって xhigh を強制しない。auto mode の作業ディレクトリ外の読み取り確認に「今回だけ許可」が増えた。含意: モデル・effort・Ultracode を別々に決める。

試すなら: claude update → 範囲の決まったタスクで /model sonnet → /effort の Tab で Ultracode だけ切り替える → MCP が落ちたら /mcp reconnect all（価格とコマンドは v2.1.284 のリリースノート、sonnet の解決先・medium 既定・fast mode なしは claude.dev「Building with Claude Sonnet 5.5」で確認済み）。

クラウドセッションが正式版に — Pro は $100・Max は $250 の専用クレジットを 10/7 までに受け取る。motani氏はルーティンで毎朝 7:00 に 27 フィード→10 本の日本語要約を Notion へ、PC は閉じたまま

— このブリーフと同じ型が、自分の GitHub リポジトリと Claude Code だけで組める。クレジットは期限つき。

motani氏（9/26）。ルーティン（クラウドで走る定期実行）のプロンプトは「手順書を読んでそのとおり実行する」だけにし、手順とスクリプトは private リポジトリに置く。既定の Trusted ネットワークでは RSS が 403 なので Custom でドメインを足すと 20 フィードから 197 件、VM は UTC なので TZ=Asia/Tokyo date を書く。一覧の「成功」は起動と終了しか意味しない。含意: クレジット（9/23 時点の契約者、クラウドセッション専用）は設定→使用量から受け取り、定期処理1本で試す。

試すなら: claude.ai の 設定 → 使用量 でクレジットを受け取る（10/7 米国太平洋時間まで） → ターミナルで /schedule daily … at 7:07am のように毎朝の定期実行を作る（正時は数分遅れるので 7:07 のようにずらす） → 環境の Network access を Custom にして読む先のドメインを足す（/schedule・Custom・正時のずれは docs/en/routines、claude --cloud は docs/en/claude-code-on-the-web で確認済み。金額と期限は BleepingComputer 9/25 と記事本文）。
