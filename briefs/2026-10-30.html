Flutter アプリの保守を Claude Code に任せたら、Crashlytics で致命的エラーに遭った利用者の割合が 1.4.1 の 8.65%（5,272 人）→ 1.4.2 の 0.63% → 1.5.0 の 0.12%（854 人）。起票 9 件中 7 件を 2 回のリリースで修正、費用はトリアージ 1 回 $0.2〜0.3・修正 PR 1 件 $0.6〜1.3（当初見積り $5〜12）（まえくん氏 10/29、Claude Code 2.1.311・Opus 5.5・Flutter 3.44）

— Flutter＋Firebase の個人アプリで「Crashlytics→issue→PR」を無人化した最初の実例。つまずき（サンドボックス・429・自己申告）がそのまま自分の設計図になる。

まえくん氏（10/29）。iOS の 2 人対戦ゲーム（直近 90 日 5,000 人超）。9 月から Mac の launchd で週 1 回 claude -p にトリアージさせ、いまは GitHub Actions が毎朝 9 時に Crashlytics と issue を突き合わせ、未起票か再発があるときだけ起動する。トリアージ・実装・レビュー・修正は別実行で前の文脈を引き継がない。Max 5x の API クレジット月 $100 の内側で、専用ワークスペースに月 $80 の上限。

自動マージの条件は、Flutter と Firestore ルールのテストが通る・レビュー 2 周以内に指摘なし・アプリのコードとテストだけ・150 行 5 ファイル以下・テストの追加か更新。つまずき: サンドボックスが PATH 上への書き込みを止めて Flutter が動かず 6 回やり直し、「Internal error」の正体は 429（Firebase CLI のログインは全員共有のクォータ）、取得に失敗しても終了コード 0 だったので成否は「PR が実際に開いたか」で判定。限界: n=1、FATAL は未捕捉の非同期例外も含む、1.5.0 は 854 人、0.1% は PR 自動化より前の成果。

試すなら: Crashlytics の取得は本人の firebase login でなく閲覧専用のサービスアカウントで（ZENGINE 氏 10/29: ロールは roles/firebasecrashlytics.viewer だけ、firebase-tools@latest mcp --only crashlytics でも共通ツール込みで 25 個読まれるので permissions.deny に firebase_deploy・crashlytics_update_issue・Bash(firebase:*)、XDG_CONFIG_HOME を専用の場所に向けて本人のログイン情報を見せない）→ 無人の claude -p には CLAUDE_CODE_RETRY_WATCHDOG=1（公式 docs/en/env-vars: 429／529 を上限なしで再試行、支出上限の 429 は即失敗、待ちは最長 5 分）→ 成否は AI の報告でなく PR の有無・ファイルの差分で判定 → 自動マージは「150 行・5 ファイル以下・テスト必須・依存とネイティブ設定は人へ」から。

Claude Code の 665 回のターン終了を 30 日分数えたら、暴走でなく「止まりすぎ」が 17%（116 回、広く取れば 24%）。止まった理由は着手の許可 54%・選択肢 39% で、人の返事の 78% は「推奨で進めて」の無修正承認。ルール追記は 23→25% で効かず、実ログの語彙で作った Stop フックは差し戻し 6 回（krbrr 氏 10/29、Windows 11）

— 「確認します」で止まる回数は体感より多い。ルールを書き足すより、止まり方の語彙をログから拾ってフックにする方が効いた。

krbrr 氏（10/29）。8/21〜9/20 の 1 人運用。判定は ~/.claude/projects/**/*.jsonl の最後の発話末尾 600 字に正規表現 STOP_ASK。対策の効果は、ルール追記 23→25%、モデル切替で 34〜35→16→7%（ルール改訂と同時期）。Stop フック初版は差し戻し 0（検出語が停止文と合わず）、語彙を作り直して 10/12〜17 に 6 回。限界: n=1、計測ごとに条件が違う、末尾しか見ないので途中で止まる型は数えない、差し戻し文の内部ラベルが報告に漏れる（6 件中 3 件）。

試すなら: 自分のログで停止の定型句（「進めてよろしいでしょうか」「どちらにしますか」など）を末尾 600 字から数える → Stop フックは「停止の定型句があり、かつ本人しか答えられない 4 類型（著者が定義）の語が無いときだけ、1 ターンに 1 回差し戻す」（記事の STOP_ASK.test(tail) && !FOUR_KINDS.test(tail)）→ 「迷ったら【仮定】タグで前進」の条項は効果が見えず著者は削除。
