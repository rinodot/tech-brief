Claude が見つけて直した 3 つ
① 完了の切り替えが「読む → 書く」の 2 手。同時の 2 回が両方 false を読み、両方 true を書く
② タグ・カテゴリを同じ名前で同時に作ると一意制約で 500（ログで確かめた）。1 文の INSERT … ON CONFLICT に
③ 使われなくなったタグの後片付けが、別の人がいま付けたタグまで消す。2xx で作った 3,330 件中 439 件でタグが消えた → 消す前に行をロックし、使用中は飛ばす（2,387 件中 0 件）
DB の作り（schema.prisma・migrations）と API の形は変えていない。止まって聞く線に当たった案: タグ・カテゴリを人ごとにする（DB の作りを変える）。Claude の推奨は「今回は見送り、別に決める」
  • 写し方: backend の写し（.env は写さない）を一時フォルダに置き、DB は Mac にもともとある Docker の postgres:15 を別の番号で立てた。認証は本番の Firebase につながず、手元だけの偽の窓口（firebase-admin が問い合わせる 1 か所に「その人はいる」と答える 10 行）で通した。新しく入れたものは無い
  • 守る約束（私が先に書いた）: ①2xx で受け付けた書き込みは消えない・化けない ②DB が戻ったら再起動なしで 30 秒以内に答える ③ある人の操作が別の人の Todo を壊さない。止まって聞く線は「DB の作りと API の形を変えること」
  • 台本（Claude が書いた）: 12 人が 75 秒、同時に作成・切り替え・更新・削除・タグの付け替え。途中でサーバーを kill して起動し直し、DB を 10 秒止め、40 人の山を足す（1 回で約 12 万回の書き込み）。終わったら DB の中身と 2xx の応答を突き合わせる。③を狙った 20 秒の台本と、DB の再起動の台本も自分で足した
  • 守れていた約束: ②だけ。DB を 10 秒止めても戻って 7〜12 ミリ秒で、サーバーの kill からは 259〜293 ミリ秒で答えた。破れていたのは①と③。③は、別の人の Todo の削除の後片付けで、こちらが 2xx で作った Todo のタグ（3,330 件中 439 件）とカテゴリ（29 件）が消えた
  • 最初の回の 500 は 736 件で、サーバーのログの操作名は createTodo 347・updateTodo 268・renameTag 121（合計 736）。ログには一意制約違反（Unique constraint failed on the fields: (`name`)）と外部キー違反が出ていた（私がログを数えて確かめた）
  • Claude は自分の台本の不備にも気づいた: 前半の回は、回をまたいで同じタグ名を使い回していたので、タグが「使われなくなる」状態が起きにくく、直す前のコードでも 500 が 0 の回があった。名前を回ごとに変えて、直す前（old4）と直した後（new4）を同じ条件で比べ直した。上の絵の数字はその 2 回
  • 止まって聞く線に当たった案は「タグ・カテゴリを人ごとにする（DB の作りを変え、データも移す）」。Claude の推奨は「今回はコードの直しだけで出し、これは別に決める」。まだ決めていない
  • 直しの副作用も報告に書いてあった: 使用中の行を飛ばすので、使われていないタグとカテゴリが 1 件ずつ残った回があった（利用者には見えない）。一括の API・merge・繰り返しの生成は台本で叩いていない。かかったのは 17 分・40 手（Opus 5.5、claude -p）

気をつけること

本番の DB に向けない台本は DB を止め、サーバーを落とす。写し（Docker の DB）だけに向ける
約束を先に書く書かないと「エラーが出なかった」を成功と見なしやすい。今回の破れ（完了の印の食い違い）は 500 にならず、突き合わせで初めて出た

自分の Chrome を、窓を前に出させずに Claude に貸す。ログインと 2 段階認証だけ自分に戻ってくる

OpenCode Browse（11/16 公開・Hacker News 330 点）。「前に出さない」「本物のクリックでしか先に進まない」はソースの行で確かめた。入れる前の安全審査は通らなかった（悪いコードは見つからず、止めた理由は自動更新）

いま
1Claude がブラウザを使うと、窓が前に出て、打っていた字が吸われるだから前に出す操作を止める仕組みを自分で足している
2ログインと 2 段階認証の前で、Claude は止まるパスワードを渡すわけにもいかず、結局ぜんぶ自分でやる
Browse を入れると
3Claude のタブは、自分の窓の後ろに畳んで開く窓を前に出す命令は、環境変数で許さない限り断る作り（下のコード）
4ログインと 2 段階認証だけ、カードで自分に回ってくる本物のクリックでしか先に進まない。ページの中のスクリプトが勝手に押すことはできない
  • ほかに: 開いている自分のタブを、ツールバーのボタンで 1 つだけ貸せる（もう一度押すと取り返す）。demonstrate で、人が手順をやって見せる間の操作を Claude に記録させられる。タブごとに readOnly（クリック・入力・移動を断る）と allowedOrigins（行き先を絞る）を付けられる（README）
  • Claude Code には MCP サーバーとしてつなぐ。渡る道具は execute・status・tabs の 3 つで、execute の JavaScript からほかの道具（navigate・snapshot・handoff など）を呼ぶ。Cloudflare や captcha の壁は解かずに人へ回す（README）

入れる前の安全審査
Claude ng・Codex 判断保留 → 入れていない・動かしていない
どちらも悪いコードは見つけていない。止めた理由は同じで、既定で毎時、配布元から新しいバイナリを落として差し替える。確かめるのは同じ配布元が出す大きさと SHA-256 だけで、署名の確認は無い（update.rs の 308 行目。signature・ed25519・minisign・cosign の語は 0 件）。だから審査したソースと、入れたあと動くものが同じだと言えない
ソースから自分でビルドした版は自動更新しない（update.rs の 1〜10 行目）。ただし手元に Rust の道具が無い
npm の本体は 5,335 バイトの起動役で、Mac 用の中身は約 5.0MB のバイナリの別パッケージ（審査で中身を読めない形）。審査したのはリポジトリのソース（Rust の中継役と Chrome の拡張）
  • 拡張の中で窓を前に出す呼び出し（chrome.windows.update(…, { focused: true })）は 2 か所だけで、どちらも人が押したとき（引き渡しの知らせのクリック・まだつながっていない間にツールバーのボタンを押したとき）。エージェントの窓とタブは、window.ts の 14〜15 行目の説明どおり「窓は focused: false で作り、新しいタブは active: false で開く」作り
  • 本人はいま、Orca 内蔵のブラウザ（Chrome のログインを取り込んだもの）でカーソルを動かさずにページを開いている。Browse が足すのは「いつもの Chrome とそのログインをそのまま使う」「2 段階認証を人に回して待つ」「やって見せて覚えさせる」の 3 つ
