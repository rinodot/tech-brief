Claude Code v2.1.280 で Opus 5.5 が全プランの既定モデルに — Pro も Sonnet 5 から切り替わる。1M コンテキスト、effort の既定は medium、以前保存した effortLevel は引き継がれない。公式ブログが「1タスクいくらか」の測り方と抑え方を公開

— 今日から起動するセッションの既定が Opus に変わる。何もしなくても挙動と消費が変わるので、/model と /effort を一度見ておく。

v2.1.280（9/22）。claude-opus-5-5 が既定の Opus になり、default は Pro を含む全プランで Opus 5.5 を指す（それまで Pro と Team Standard は Sonnet 5）。API 価格は入力 $4／出力 $20／キャッシュ読み $0.20 per Mtok（Opus 5 より入出力 20%・キャッシュ読み 60% 安い）、1M コンテキスト。effort の既定は medium。旧形式の effortLevel は Opus 5.5 に効かず、/effort で選ぶまで既定のまま。

同日の公式ブログ（Addy Osmani）の型: /usage で残量、/effort は日常は medium、詰まったら high、機械的な作業は low。/compact は 150K の会話で約 $0.25 かかるので節目だけ、/clear は無料。CLAUDE.md は 200 行未満。検索やログ読みはサブエージェントに model: haiku か sonnet を書いて回す。含意: 既定が Opus になった分「重いモデルを軽い設定で」が基本形。サブスクの消費の重みは明記がないので /usage の減り方を見る。

試すなら: claude update → /model で既定が Opus 5.5 になっているか見る → /effort status で medium を確認し、上げるなら /effort high を Enter で保存（Opus 5.5 用に別枠で保存される）→ 検索役のサブエージェントの frontmatter に model: haiku を足す（既定モデル・effort の挙動は docs/en/model-config、価格と手順は claude.com/blog の 9/22 記事で確認済み）。

出典: Claude Blog — What a task costs on Opus 5.5（Addy Osmani、9/22）。リリース: github.com/anthropics/claude-code/releases/tag/v2.1.280

無人の claude -p で「書き込み禁止」にしたつもりが3か所で開いていた — Write(パス) は読まれない、~/.claude/settings.json の defaultMode: auto は -p にも効く、Write を外しても Bash の > は Edit ルールで通る

— 9/14（deny の Write(パス)）と 9/21（GitHub Actions 63営業日）の続き。夜間バッチの権限は「ツール名」でなく「モード＋Edit(パス)」で組む。

masamitsu_sera氏（9/22、v2.1.266）。①Write(パス) は受理されても参照されず、Edit(パス) で書く。②ユーザー設定の "defaultMode": "auto" は -p にも効き、書き込みが通った。設定ファイルは組み込み既定に勝つので --permission-mode dontAsk を必ず付ける。③Write を外しても printf 'x' > file は Edit の allow 範囲なら成功する。含意: 止めるのは Edit(パス) の範囲と Bash の有無で、Write の有無ではない。

試すなら: 無人ジョブは claude -p "<prompt>" --permission-mode dontAsk --allowed-tools "Read,Glob,Grep" --disallowed-tools "Bash,Write,Edit" --output-format stream-json を型にし、結果はファイルでなく最終メッセージで受け取る → --debug-file debug.log に起動時の「is not matched by file permission checks」警告が出ていないか見る（①〜③は docs/en/permissions と docs/en/permission-modes に同じ記述があり、後者の CI 例も -p … --permission-mode dontAsk --allowedTools の形）。

出典: Qiita — 無人の claude -p に書込を閉じたつもりが、3つの見落としで開いていた

月額600円のサブスクで、Gemini の原価が月6,000円だった — 見積もりは出力トークンを 3,000 と置いて 2.7倍ずれ。無料枠の回数はモデルごとに別に数えられるので、9モデルに順送りすると 1日20回→1,130回（Matthew氏、9/21）

— AI 機能の値付けは、モデルの表示価格でなく usageMetadata の実測トークン×利用回数で決める、という実例。

Matthew氏（9/21、React＋Firebase の英単語アプリ）。gemini-3.8-flash（出力 $3.75 per 1M）で1検索が出力約970トークン・約0.67円。1日300語なら月6,030円、売価は月600円。見積もりは出力を3,000トークンと置いて 2.7倍ずれた。対策は上限を1日100語にし、無料枠はモデルごとに数えられるので Flash 系（20回／日）と Lite 系（500回／日）を9本並べ、429 で次へ送る。含意: 原価は「1回の円×回数上限」で先に確定させる。

試すなら: 自分の Gemini 呼び出しの usageMetadata（promptTokenCount／candidatesTokenCount）を10回分ログに出し、中央値×想定回数×単価で月額を出す → 無料枠のモデル別 RPD は AI Studio の Rate limits 画面で確認し（公式ページは「プロジェクト単位、API キー単位ではない」とだけ記載）、429 時のフォールバック先を決めておく。

出典: Zenn — 個人開発のLLMアプリ、原価を計算したら月額600円で原価6,000円だった
