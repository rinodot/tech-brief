Claude Code に「進めて」と打つ回数が 12.5%→2.3% に — tasks/todo.md に - [ ] が残る間は Stop フックで応答終了を差し戻し、未 push のコミットも止める。「本当に出た？」には本番の SHA・ルートの実バイト数・直近5分のログの3証拠で答えさせる

— 9/27 特集②の「CLAUDE.md はお願い、止めるのはフック」を、自分の催促の回数で測った個人開発の実例。終わりの条件をフックに書けば、私の「進めて」も減る。

momozaki氏（9/27）。7/15〜8/17 は「進めて」だけの1行が 96 件（12.5%）、「まだ？」「残タスクは？」を足すと 135 件（17.5%）が催促だった。①Stop フック continue-guard.js: tasks/todo.md に - [ ] が残っていれば {"decision":"block"} で応答終了を差し戻す。条件は 30 分以内に更新された todo だけ・1セッション 2 回まで・stop_hook_active が true なら判定しない。②unpushed-guard.js: 30 分以内のコミットが未 push なら差し戻す。③「本当に出た？」は deploy-verify が本番の SHA とデプロイ時刻・各ルートの status と実バイト数・直近 5 分のログの 3 証拠をそろえるまで「出た」と言わせない。

8/25〜9/27 の 1,439 件では「進めて」33 件（2.3%）、「まだ？」0、「残タスクは？」3。著者は環境やモデルの更新が重なったため「全部がこのフックの効果とは言えない」と明記。含意: 催促は Claude が終わりの条件を持たない症状で、フックに書けば回数で効果を測れる。

試すなら: ~/.claude/settings.json の hooks.Stop に {"type":"command","command":"node ~/.claude/scripts/continue-guard.js"} を足し、スクリプトは stdin の stop_hook_active が true なら exit 0、tasks/todo.md に - [ ] が残るときだけ {"decision":"block","reason":"todo.md に未完了があります"} を出す → 差し戻し回数の上限は自分で数える（Claude Code 側は連続 8 回で無効化、CLAUDE_CODE_STOP_HOOK_BLOCK_CAP で変更。Stop の decision: block・stop_hook_active・8 回の上限は docs/en/hooks と hooks-guide で確認済み。件数と 3 証拠は記事本文）。

— 9/30 の「キャッシュは 60 分で消える」の続き。出力を削るより、文脈に入る前に削る。flutter test の出力も同じ構造で、フックの形はそのまま写せる。

Antoine van der Lee氏（9/28）。1,674 セッションの集計で、トークンの 94.2% はキャッシュ読み、出力は 0.6%。費用は文脈の大きさ×ターン数で決まる。ビルド 13,323 回のうち 48% がフィルタなし。対策は PreToolUse フックで、フィルタのないビルドに | xcsift を足した command を updatedInput で返す（18,200→32 トークン）。ほかにサブエージェントの 85% が親のモデルを継承。含意: 指示は守られない前提で、コマンドの書き換えをフックに落とす。

試すなら: .claude/settings.json の hooks.PreToolUse（"matcher": "Bash"）に小さなスクリプトを置き、flutter test に --reporter が無ければ --reporter failures-only（失敗したテストだけ出力）を付けた command を {"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow","updatedInput":{"command":"…"}}} で返す → 探索用サブエージェントは .claude/agents/*.md に model: sonnet を明記（updatedInput は docs/en/hooks、--reporter failures-only は flutter_tools の test.dart で確認済み。数字は記事本文で対象は Xcode。記事にはスポンサー製品の言及あり）。

Whisper が無音で「ご視聴ありがとうございました」を連呼する原因は「直前の出力を次の窓のプロンプトに使う」既定 — condition_on_previous_text=False だけで 44 分の会議の書き起こしが 1,300 字→5,600 字。用語集を initial_prompt に入れると逆効果（類似度 0.526→0.380）

— 9/12 の Whisper LoRA、9/26 の Flutter×ローカルLLM に続く音声側の実用値。引数名は faster-whisper でも同じなので、私の GPU にそのまま移せる。

ひろたに氏（9/29、Mac mini M4）。Whisper は既定で直前の出力を次の窓のプロンプトに使うので、無音で出た幻聴が自己増殖する。condition_on_previous_text=False だけで 1,300 字が 5,600 字に戻った。類似度は large-v3 0.659、turbo 0.526、用語集を initial_prompt に足すと 0.380 に低下。44 分の音声で turbo 約 2 分、large-v3 約 6 分 45 秒。含意: 幻聴対策はモデル変更でなく引数 1 つ。

試すなら: faster-whisper なら model.transcribe(path, language="ja", condition_on_previous_text=False, vad_filter=True)（VAD で無音区間を落とす）→ 用語集は initial_prompt でなく後段の LLM に渡す → Ollama の要約は num_ctx を 16384 に（condition_on_previous_text・vad_filter は faster-whisper の transcribe.py で確認済み。数字は記事本文、Mac の mlx-whisper での値）。
