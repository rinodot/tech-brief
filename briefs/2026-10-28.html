MCP の道具 40 個を「一覧」と「呼び出し」の窓口 2 本の裏に隠しても、節約できる前払いは道具 1 個あたり約 15 トークン（39 個で 587）だけ。窓口から一覧を 1 回取ると 4,225 トークン払う（1 対 7.2）。道具を 1 回しか呼ばない仕事では窓口方式の方が高く、費用は約 $0.055 対 $0.073〜0.076。偽物 39 個を混ぜても呼び間違いは 12 回中 0（ぬまーん氏 10/27、Claude Code 2.1.302・Sonnet 5.5）

— 「MCP が多いと文脈を食う」と聞いて窓口（ゲートウェイ）に束ねる人が増えているが、tool search が既定の今は名前だけ先に載るので前払いは小さい。束ねる前に自分の道具数で測る値打ちがある。

ぬまーん氏（10/27）。自作 MCP に本物 1 個＋似た名前の偽物 39 個を入れ、A1（1 個を直接）・A40（40 個を直接）・G／Gn（list_capabilities と invoke の窓口 2 個）の 4 条件を各 3 回、claude -p（2.1.302、Sonnet 5.5）で測定。初回ターンの入力合計は A1 36,000・A40 36,587・G 36,061・Gn 36,013 トークンで、道具 1 個あたり 15.051 トークン。39 個増やしても +587 にしかならない。

一方、窓口から一覧を 1 回取ると入力が +4,225（一覧は 40 件 10,862 バイト）。最終ターンの入力は A40 37,090〜37,372 に対し窓口 40,816〜40,916、ターン数は 4 対 5、再利用した入力の累計は約 139k→約 182k。温まった状態の費用は A1 約 $0.050・A40 約 $0.055・窓口 約 $0.073〜0.076。偽物 39 個を混ぜても呼び間違いは 12 回中 0 で、名前が説明的なら 40 個までは選択は崩れない。含意: 1 回呼ぶだけの仕事に窓口は損。限界: 自作 1 本・各 3 回、繰り返し呼ぶ仕事や検索つき窓口は未検証。

試すなら: 自分の MCP 構成で初回ターンの入力を測る: claude -p "＜1 回で終わる依頼＞" --output-format stream-json --verbose --mcp-config cfg.json --strict-mcp-config --permission-mode acceptEdits --allowedTools "mcp__＜server＞"（acceptEdits だけでは MCP の道具が拒否された）→ 道具を直並べにした設定と窓口 2 本に束ねた設定で、usage の入力合計（input＋cache_creation＋cache_read）とターン数を比べる → tool search が既定の環境では MCP の道具定義は必要時に読み込まれる（公式 docs/en/prompt-caching の「Tools deferred」）ので、束ねる理由は「道具の選び間違い」が実際に出た時だけにする。

Claude Code は起動フォルダから上の全階層の CLAUDE.md／CLAUDE.local.md を読む（CLAUDE.md が 1 つも無ければ AGENTS.md も）。だから Downloads やホーム直下で claude を起動すると、ブラウザが黙って置いたファイルが指示になる。研究元の自社検証では Claude Code が .claude/settings.json に ANTHROPIC_BASE_URL を書かされたのが約半数、Codex は 9 割超（ほし氏 10/28、SupportApp3 Lab・遠藤氏 10/27）

— 「Downloads で claude を開いてファイルを見てもらう」は誰でもやる。点検コマンド 2 行と「プロジェクトのフォルダでしか起動しない」で塞げる。

ほし氏（10/28）。研究元 Forever Security（10/22）は第三者検証なし。Codex は ~/.codex/config.toml に攻撃者の MCP サーバーを書かされ、同社いわく「直すものは無い」＝仕様。ほし氏は --dangerously-skip-permissions 常用で Downloads 直下 295 項目。SupportApp3 Lab は上位階層の指示ファイルを一覧する bash、遠藤氏は managed settings の PreToolUse hook で設定変更を止め攻撃役 80 本で確認。

試すなら: ls -a ~/Downloads | grep -i -E 'agents(\.override)?\.md|claude\.md|^\.claude$|\.mcp\.json' と grep -n "ANTHROPIC_BASE_URL" ~/.claude/settings.json ~/Downloads/.claude/settings*.json で心当たりのない設定が無いか見る（ほし氏の点検）→ 見覚えのない ANTHROPIC_BASE_URL や MCP サーバーがあれば設定を消してログアウト・再ログイン → 起動前に pwd、Downloads・デスクトップ・ホーム直下では起動しない。見てもらうファイルは作業フォルダにコピーしてから → 上の階層の CLAUDE.md を切るなら claudeMdExcludes（公式 docs/en/memory）、会社支給機なら managed settings の PreToolUse hook（"onFailure": "block"、v2.1.295 以降）で settings.json の変更を止める。

日本語の文字起こし 11 モデルを無料の T4 で比較: 読み上げ（FLEURS 650 発話）の 1 位 Qwen3-ASR-1.7B は CER 5.36% だが、放送音声（ReazonSpeech 1,000 発話）では 25.98% で 8 位。両方で崩れないのは parakeet-tdt_ctc-0.6b-ja（6.37%／11.21%、1 発話 約 0.05 秒）と whisper-large-v3-turbo（6.03%／13.64%）。順位の相関は 0.24、Whisper は 88 文字の文に 506 文字を出す暴走 1 件が誤りの 22〜25%（JA Model Bench 10/27）

— 10/18 の特集以来探していた「NVIDIA 上の日本語 CER 比較」。読み上げの順位で選ぶと現場の音声で外す、という数字が揃った。

JA Model Bench（10/27）。Colab 無料 T4、fp16、日本語指定、初期プロンプトなし、原則 greedy。他の CER（読み上げ／放送）は large-v3 6.10／14.78、kotoba-whisper-v2.0 6.99／11.80、reazonspeech-nemo-v2 7.46／11.00（放送と同じコーパスで学習したモデルは有利）。large-v3 の暴走 1 件を除くと 4.58%。限界: T4 で 1 回だけ、読み上げの 2〜5 位は信頼区間が重なる、「暴走除外」は後付け。

試すなら: 自分の用途に近い音声を数十件用意し、候補を 2〜3 個（放送・会議なら parakeet-tdt_ctc-0.6b-ja と whisper-large-v3-turbo、読み上げなら Qwen3-ASR-1.7B）に絞って CER を測る（記事は NFKC 正規化後に句読点・記号・空白を除いて算出、数字の読みは変換しない）→ Whisper 系は同じ語句の長い繰り返しを検出して切る（暴走 1 件で全体の誤りが 2 割動く）→ 1 位だけで選ばない（読み上げの 2〜5 位は誤差の範囲）。
