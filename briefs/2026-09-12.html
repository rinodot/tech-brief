自作 Skill が「呼ばれるか・効いているか」を数字で測れるようになった — claude plugin eval はプラグインあり／なしで各3回走らせ、差分 Δ を出す

— Skill の description を勘で直すのをやめ、Δ で直せる。ただし実行は自分の枠を消費する。

v2.1.269（9/11）で入った。プラグインの evals/ に「利用者が打ちそうなプロンプト＋採点器」をケースとして置き、claude plugin eval . で回す。1ケースは既定でプラグインあり3回・なし3回の計6回。採点器は6種、regex・tool_used・tool_order・file_exists は転写とファイルから判定して無料、llm と baseline は判定モデルを呼ぶ。結果は WITH／W/OUT／Δ の表と HTML レポートで、公式の例は first-case 1.00 0.33 +0.67 6 $0.41。

ケースは claude plugin eval init で Claude に書かせられる。プラグインを読んで「発火すべき／すべきでない」プロンプトと採点器を提案し、1回試してから書く。公式が挙げる最初のつまずきは「Δ がほぼゼロで tool_used: Skill が落ちる」＝自然な言い回しでは Skill が選ばれていない状態で、直すのは description。含意: 全実行が自分のプランの使用量に乗る。まず1ケース・--ablation none（片腕だけで費用半分）から。

試すなら: claude --version で 2.1.269 以上を確認し、プラグインのルートで claude plugin eval init → claude plugin eval . --case <name> --runs 1 --ablation none で1回だけ回して採点器の挙動を見る。同じリリースで bashEditDiffEnabled（Bash 経由の編集も差分表示）と /output-style のヘッドレス対応も入った。

試すなら: 自分の録音を Silero VAD で切り、同じ区間で「素の turbo」の CER を先に測る。改善幅は評価セットが未観測かどうかで割り引いて読む。

「日本語は1文字1トークン」は一世代前の話 — 6トークナイザーの実測で、現行世代は文字数×0.7〜0.8

— RAG のチャンク上限と費用見積もりが3割ずれている可能性。

AI仕事ラボが9/10に公開。16ジャンル40本・9,676字を計測。1文字あたり o200k_base（GPT-4o）0.71、cl100k_base（GPT-4）0.97、Gemma 0.58、Claude 1〜2世代 0.97。現行の Claude と Gemini は非公開で未計測。漢字0.87、ひらがな0.62、ASCII 0.38、全角英数1.55。目安は「現行世代は文字数×0.7〜0.8、GPT-4世代は×1.0」。含意: ローカルの Gemma なら見積もりを4割下げてよい。

試すなら: 自分の RAG 文書を tiktoken の o200k_base と使うモデルのトークナイザーで数え、チャンク上限を文字数でなくトークンで決める。
