GoogleのAndroid SkillsはClaude Codeにそのまま入る — 中に「Play審査の事前監査」がある

— Flutterアプリの Android 側の作業と、自分のSkills設計の両方に効く。

Android Studio Quail 4のAndroid Skillsは、GitHubのandroid/skillsで公開され、Claude Codeのプラグインとしてそのまま入る。22個のSKILL.mdが登録済みで、AGP 9アップグレード、Navigation 3、R8解析など。Flutterでもandroid/配下はAGPで動くので、ネイティブ側にそのまま効く。

設計が勉強になる。play-policy-insightsはPlay審査の3領域（権限、アカウント、データセーフティ）をコードと申告の突き合わせで監査する。Pythonのオーケストレータが静的解析と目標の列挙を済ませ、LLMは「サブエージェントを呼べるならMode A（並列）、呼べなければMode B（順に自走）」と分岐する。ワーカーへの契約は「結果はJSONでファイルに書け、返事は『SUCCESS』だけ」で親の文脈を汚さない。Googleの原則は「既に知っていることは教えない」「スキル1つで毎回100〜200トークン」「評価はスキルありで通り、なしで落ちる」。含意: 自作Skillsの採用基準と検収基準を、そのまま借りられる。

試すなら: Claude Codeで /plugin marketplace add android/skills → /plugin install android-skills@android-skills。Flutterプロジェクトの android/ で「AGP 9に上げて」と頼むと agp-9-upgrade が自動で効く。

出典: android/skills

claude -pの無人実行が組める形になった — 確認を待たず、拒否して進む

— 夜間バッチやCIにClaude Codeを置くとき、途中で止まる要因が消える。

v2.1.259で--permission-prompts noneが入った。確認が要る操作はPermissionRequestフックが許可しない限り拒否され、Claudeには「承認者はいない、再試行するな」と伝わる。--permission-mode autoと組めば、分類器が通したものだけ動く。--bareはhooks・Skills・MCP・CLAUDE.mdの自動読み込みを飛ばし、必要な文脈だけ--mcp-config等で渡す。将来-pの既定になる。含意: 定期ジョブの再現性はこの2つで作る。

試すなら: claude --bare -p "テストを実行して失敗を直して" --permission-mode auto --permission-prompts none --output-format json | jq '.result, .total_cost_usd'（ANTHROPIC_API_KEY が必要）

出典: Claude Code docs — Run programmatically

実例: 「判断は委ね、壊れないよう囲う」— 8月末時点のひとりのClaude Code設定

— auto modeを常用する構成の、具体的な囲い方が1本にまとまっている。

kawarimidoll氏が8/31にZennで公開した設定。settings.jsonは3行で、"defaultMode": "auto"、助言役を別モデルにする"advisorModel": "fable"、表示を絞る"viewMode": "focus"。囲いは2段で、書き込みはcage、読み取りとコマンドはguard-and-guideで絞る。検証はagent-browserとterminal-useに任せ、計画とログはz-ai/へ。含意: auto modeの安全を境界で作る話の、個人規模の例。

試すなら: settings.jsonに {"permissions":{"defaultMode":"auto"},"viewMode":"focus"} を足し、計画・ログ用の z-ai/ をグローバルの gitignore に入れる。
