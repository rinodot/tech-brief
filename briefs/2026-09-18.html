VRAM 8GB の5年前の PC で 35B の MoE モデルが 20 t/s — llama.cpp の --n-cpu-moe でエキスパートの重みだけ CPU に逃がす

— 12〜16GB の GPU なら同じ手で 27B〜35B 級の MoE を「載る前提」で動かせる。

「引退間際の非エンジニアがAIと遊ぶ」氏（9/17）が Core i5-10400・RTX 2060 Super 8GB・DDR4 64GB で、Unsloth の Qwen3.6-35B-A3B-UD-Q4_K_M（MoE。総35B、1トークンで動くのは約3B）を llama.cpp b10919 で動かした実測。鍵は -ngl 99 で全層を GPU に送りつつ --n-cpu-moe 48 で先頭48層のエキスパート重みだけ CPU 側に残すこと。毎トークン使うエキスパートは一部なので、重い部分を RAM に置いても注意機構と KV キャッシュが VRAM にあれば速度が出る。-ctk q4_0 -ctv q4_0 で KV キャッシュを約1/4 に、--spec-draft-n-max 2 で MTP（2トークン先読みの投機生成）を有効化。

結果は生成 12〜24 t/s、プロンプト処理は最大 81.5 t/s。goose で使うと「アクティブなエキスパートが2つ以上同時に立ち上がって」VRAM から溢れ、10 t/s 程度に落ちた。含意: 12〜16GB なら --n-cpu-moe を減らして GPU に載せる層を増やせる分、27B〜35B の MoE が実用域に入る。

試すなら: llama-server -m Qwen3.6-35B-A3B-UD-Q4_K_M.gguf -ngl 99 --n-cpu-moe 48 --spec-draft-n-max 2 -ctk q4_0 -ctv q4_0 -c 12288 -b 128 -ub 128 で起動し、起動ログに loading MTP tensors が出るか確認 → nvidia-smi を見ながら --n-cpu-moe を 4 ずつ減らし、VRAM が溢れる直前の値で止める（フラグ名は llama.cpp の common/arg.cpp で確認済み。密なモデルには --n-cpu-ffn）。

出典: Zenn — 5年落ちゲーミングPCでもローカルLLMは戦える（llama.cpp MoEオフロードチューニング編）

Claude Code v2.1.274: ヘッドレス実行が「繋がらない MCP サーバー」を待つ時間を CLAUDE_CODE_MCP_STARTUP_WAIT_MS で切れる — 33.4秒→3.5秒

— cron や CI から claude -p を回すたびに黙って30秒消えていたなら、環境変数1つで消える。

9/17 の v2.1.274 で追加。非対話（claude -p）の最初のターンは、接続中の MCP サーバーが揃うまで待つ。石川覚氏（9/17）の計測では、MCP なし 3.6秒、繋がらないサーバーが1つあると 33.4秒、=0 を付けると 3.5秒。0 は「待たない」で、遅れて繋がったサーバーのツールはそのターンには来ない。含意: MCP を使わない定期実行は 0、使うなら 5000 程度の上限にし、--strict-mcp-config で必要なサーバーだけに絞る。

試すなら: time claude -p "Reply with exactly: ok" --max-turns 1 --strict-mcp-config --mcp-config .mcp.json を素の状態と CLAUDE_CODE_MCP_STARTUP_WAIT_MS=5000 付きで比べる。差が大きければ、どのサーバーが接続に失敗しているかを /mcp で確認して設定から外す。

出典: GitHub — anthropics/claude-code Release v2.1.274

Google Play の日本向け売上に「代金回収の承認」が必要になった — 招待メールの期限（Hidenori氏の例では 2026年12月1日）を過ぎると全地域の支払いが保留

— 有料機能や課金がある Play アプリの開発者は、メールと Play Console の通知を一度確認しておく。

Google のヘルプによると、日本で販売する／日本から販売するデベロッパーは、資金決済法（PSA）に基づき Google が代金回収代理人になることを承認する必要があり、招待状の期限を過ぎると「すべての地域におけるすべての収益がグローバルに保留」。個人開発者 Hidenori氏（9/17）に届いたメールの期限は 2026年12月1日で、PSA はボタン1つで完了、割賦販売法（ISA）側の追加確認は同氏にはまだ来ていない。含意: 売上がある Play アプリなら、メールを探して1分で済ませておく。

試すなら: メールで「代金の回収を承認してください」を検索 → なければ Play Console のお支払いプロファイルとお支払いセンターの通知を確認 → [Authorization] → ［続行］ → ステータスが更新されたことを見る。組織アカウントは ISA で法人番号と過去5年の法的措置に関する質問2問が加わる。

出典: Google お支払いセンター ヘルプ — 日本で販売する、または日本以外で販売するデベロッパーとして本人確認を行う方法
