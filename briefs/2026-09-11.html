レガシー500本からのSQL抽出を claude -p --tools "" で回し、Haiku・Sonnet・Opus を同じ866文で比べた — 取りこぼしゼロは Opus だけ、しかも最速

— 「大量処理は安いモデルで」の前提を、数字で一度疑う。

クラスメソッドの田中聖也氏が9/11に公開。Java 300本・VB.NET 200本の計500ファイルからSQLを抜く作業を、ファイル探索はさせず --tools "" でツールを全部切り、外部スクリプトから claude -p を1ファイルずつ呼ぶ形で組んだ。第1弾は500ファイルから440文を抽出。精度検証は1ファイル4〜8文を含む100ファイル・866文の正解データで、3モデルを同条件で比較。

Haiku 4.5 は再現率99.9%（取りこぼし1）、$4.25、21.0分。Sonnet 5.0 は99.8%（取りこぼし1・余計な抽出1）、$7.07、7.4分。Opus 5.0 は100%（どちらもゼロ）、$9.04、6.7分。著者の結論は「Opus のみが全項目クリーン」「安い＝速いではない」。含意: 決定的な作業では単価より「やり直しゼロ」と所要時間を先に見る。差額$4.79で21分が6.7分になり検品が消える。月次で繰り返す処理ほどこの差は積み上がる。

試すなら: cat file.java | claude -p --tools "" --output-format json "このコードのSQL文だけを列挙" のように標準入力で渡し、まず正解つきの小さな検証セットで3モデルの取りこぼし数と時間を測る。

出典: DevelopersIO — レガシーコード500本からSQLを自動抽出できるのか試してみた

Flutter 本体から Material と Cupertino が出た — material_ui／cupertino_ui 1.0.0 へ dart fix で載せ替え、以後はウィジェットの更新が週次で来る

— 手元のアプリの import が全部対象。次の flutter upgrade の前に。

Craig Labenz 氏が9/9に告知。flutter/material.dart と flutter/cupertino.dart を8月に pub.dev の material_ui・cupertino_ui 1.0.0 として同一内容で公開し、切り離しを完了。dart fix で pubspec.yaml に2パッケージを足し、import を置き換える。狙いは3か月周期の安定版を待たない週次リリース。「ドロップインで済むはず」とあり、旧 import の期限は未記載。含意: UI 部品の修正が本体と別の速度で来る。

試すなら: dart fix --dry-run で置換対象の import 数を見て、テストが通るのを確認してから dart fix --apply。pubspec の2パッケージは 1.0.0 で固定。

出典: Flutter Blog — Material and Cupertino decoupling are here

Google Play の手数料が日本では9/30から変わる — 年間収益100万ドル未満は10%へ、標準は新規インストール20%・既存25%

— 収益に直接効く期限。自分が「引き下げ枠」に登録済みかを今のうちに。

日本とオーストラリアは2026年9月30日から、その他地域は2027年9月30日から。年間収益100万ドル未満は非定期・定期とも10%＋請求手数料（該当する場合）、標準は新規インストール20%・既存25%、定期購入は10%。新規／既存は「開始日以降に Play から初めてインストールか初めて更新したか」で決まる。請求手数料は米英EEAで5%、他地域は後日。含意: 現行の15%枠は「関連付けられているデベロッパー アカウント」でアカウントグループを作って登録する方式。未登録なら先に。

試すなら: Play Console の「関連付けられているデベロッパー アカウント」で登録状況を確認し、10/1以降の収益レポートで新規／既存の区分と適用率を1回見る。
