— 定期実行の「1 回いくら・どこで止まるか」を台帳で出した実例。止まり方 6 つは自分の自動化にも全部当てはまる。

crossclub 氏（11/2）。Windows のタスクスケジューラで claude -p を 1 日 14 回、41 日。10/22〜10/31 の台帳は 76 回中モデル呼び出し 65 回・失敗 5 回・合計 $14.09（total_cost_usd の従量換算、契約は Max 5x）。平均は daily $0.46（9 回）、bid $0.08（33 回、11 回は呼ばず $0）、fix $0.24、review $0.41。上限は daily＝sonnet・40 ターン・$4、bid＝haiku・15 ターン・$1。

止まった所 6 つ: ①節約モード FRUGAL が週使用 36% で誤発動 ②13 回で操作が許可で拒否（計 22 件）、しかも成功扱い ③error_max_turns 5 回 ④木曜午後に週枠 90% 超で 3 回が未実行 ⑤未公開の記事を「公開」と誤報告 ⑥メール読取が接続切れと Resource exhausted で失敗。直し: --model を毎回渡す（渡さないと Opus）、拒否された操作は手順書に書いて blocked に、成功した回だけ日付つきの完了印。台帳は 10 日分、収益は 1 円。

試すなら: 定期実行の各回を claude -p … --output-format json にして total_cost_usd・subtype・permission_denials を 1 行 JSON で台帳に追記し、「成功扱いの拒否」を数える → 公式 docs/en/headless（11/3 確認）: 答える人がいない実行は --permission-prompts none（v2.1.259〜。拒否は stream-json の permission_denials に出る）、-p は v2.1.302〜何も指定しないと Manual モードで始まり承認が要る呼び出しは拒否、--bare は「スクリプト向けの推奨で将来 -p の既定になる」が購読ログインを使わない（API キーが要る）→ 週枠の区切り時刻（記事は木曜 22 時）の直前に重い回を寄せない。

v2.1.314 の blockWritesOutsideWorkingDirectories は Write／Edit／NotebookEdit だけに効き、Bash の echo ＞・cp と PowerShell の Set-Content・＞ は作業フォルダの外へ書けた（Windows 11・2.1.316 の実測。設定なしは Write 8/8 成功→設定ありで 7/7 拒否）。21 行の PreToolUse フックで 3 件止めたが ~・/tmp・$HOME・UNC の 6 パターンは素通り（tamao 氏 11/2）

— 10/31 に載せた新設定の「効く範囲」。公式 changelog どおり Bash は対象外なので、設定だけで安心しない。

tamao 氏（11/2、Windows 11・2.1.316）。設定なしでは外への Write 8 通りが成功、設定ありで 7 通り全部拒否。一方 Bash の echo ＞・cp と PowerShell の Set-Content・＞ は外へ書けた。公式 changelog も「Write, Edit and NotebookEdit refuse paths outside」で Bash は対象外。補いの 21 行 PreToolUse フックは外 3 件を止めたが ~・$HOME・/tmp・UNC など 6 パターンは素通り。

試すなら: ~/.claude/settings.json に "permissions": {"blockWritesOutsideWorkingDirectories": true} を入れ、まず Write で外へ書かせて拒否されるのを確認 → Bash 側は設定では止まらないので、macOS／Linux／WSL2 ならサンドボックス、Windows なら PreToolUse（matcher Bash|PowerShell、exit 2 で拒否）を「書き先の間違いを手前で止める保険」として置く → 文字列判定は ~・$HOME・/tmp・UNC を通すので、守りたいものは別フォルダにバックアップしておく。

12GB の RTX 3080 Ti（中古 82,000 円）で gpt-oss-20b MXFP4（11.27GiB）が pp512 4,705・tg128 177.5 tok/s、Ryzen AI Max+ 395 の内蔵 GPU の約 2.4 倍／2.2 倍。ただし軽い負荷では GPU が P3・780MHz に留まって生成が約半分の 87.8 tok/s になり、nvidia-smi -lgc でクロックを固定して解消（MASAYUKI KOBAYASHI 氏 11/2、llama.cpp Vulkan）

— 12GB でも 20B の MoE は全層載って 170 tok/s 台。速度が半分しか出ないときは、まず nvidia-smi で pstate とクロックを見る。

MASAYUKI KOBAYASHI 氏（11/2）。外付けの 3080 Ti 12GB、llama.cpp（Vulkan）。gpt-oss-20b MXFP4 11.27GiB は全層が載り、内蔵 GPU の pp512 1,929／tg128 79.0 に対し 4,705／177.5。63GB の 120b は分担しても 56.0→55.3。落とし穴は省電力: 生成だけの軽い負荷では P3・780MHz に留まり 87.8 tok/s と半分、nvidia-smi -lgc／-lmc でクロックを固定すると戻る（再起動で解除）。

試すなら: nvidia-smi --query-gpu=pstate,clocks.sm,clocks.mem --format=csv -l 1 で生成中の pstate を見る → P3 に張り付くなら sudo nvidia-smi -lgc 1500,2100 と sudo nvidia-smi -lmc 9501,9501（数値は自分のカードの上限に合わせる。戻すのは -rgc／-rmc、再起動でも戻る）→ 測り直しは llama-bench -m ＜gguf＞ -ngl 99 -p 512 -n 128 -r 3（記事は Vulkan、CUDA は未確認）。
