RTX 5070 Ti 16GB で Ollama を常駐させる知見: モデルが退避される原因は VRAM でなく OLLAMA_MAX_LOADED_MODELS（著者環境で 1）。3 に固定し、4 にすると gemma4:12b が 76→16 tok/s。再起動後に残った llama-server.exe 7 個で 80→6 tok/s になっても ollama ps は「100% GPU」のまま（Ace 氏 11/7）

— 12〜16GB で「遅いのは GPU のせい」と思う前に、設定値と残存プロセスを疑う順番。ollama ps が正常でも遅い、は私の構成でも起こりうる。

Ace 氏（11/7）。RTX 5070 Ti 16GB で、自作 MCP でローカルモデルに下書きを振る。gemma4:12b-it-qat 7.4GB・77 tok/s、qwen2.5-coder:14b 9.1GB・71〜73 tok/s。退避の原因は著者環境で 1 だった OLLAMA_MAX_LOADED_MODELS（公式既定は GPU 数×3）で、3 に固定。4 だと 12b が 76→16 tok/s。再起動後も llama-server.exe が 7 個残り 80→6 tok/s、ollama ps は 100% GPU 表示のまま。

試すなら: Ollama の環境変数に OLLAMA_MAX_LOADED_MODELS=3（docs.ollama.com FAQ: 既定は GPU 数×3、Windows はユーザー環境変数に書いて Ollama を再起動）→ 遅くなったら ollama ps の PROCESSOR 列だけでなく nvidia-smi の使用メモリと残存プロセスを見る（Windows は Get-Process llama-server,ollama,'ollama app' | Stop-Process -Force、記事のコマンド）→ 埋め込み用 nomic-embed-text（0.30GB）は生成モデルと同居させ、RAG の往復スワップを消す。4k 文脈・n=1、ollama run が固まるので著者は API 経由で計測。
