deny に書いた Write(パス) は一度も参照されない — ファイルの許可・拒否で効くのは Read(…) と Edit(…) だけ

— 自分の settings.json の deny が「書けているのに効いていない」かを1分で確認できる。

Quintet Kit氏（9/12）が "deny": ["Write(src/generated**)"] が無視されていたと報告。公式仕様では、ファイルのパス規則は Read(path) と Edit(path) だけを照合し、Write・NotebookEdit・Glob・MultiEdit にパスを付けた規則は受理されるが参照されず、起動時に警告が出る（v2.1.210以降）。Bash 側は最初の * より前が一致条件なので、Bash(git * main) は git 全部を許す。含意: 起動時の警告を一度は読む。

試すなら: claude 起動直後の警告を読み、Write(...)／Glob(...) は Edit(...)／Read(...) に書き換え、* はサブコマンドの後ろに置く（Bash(git diff *)）。npx @quintetkit/ccheck でも検出できる。

出典: Zenn — 書いた deny ルールが、一度も参照されていなかった

ローカルLLMの JSON 出力で「後ろの欄だけ空」になるのは、Pydantic の既定値が required から落ちるから — 全項目を必須にして空欄率 59%→0%

— Ollama で構造化出力を使っているなら、スキーマ側の1関数で直る。

juzo1192氏（9/12）。Ollama の26Bモデル・温度0.2〜0.3で14項目の JSON を出させると、最後の項目が245件中59%で空だった。Pydantic は既定値を持つ項目を required に入れないため、Ollama の文法制約では省略可能になり、低温度では早く } を閉じる。直し方は __get_pydantic_json_schema__ を上書きして schema["required"] = list(props) とし、LLM に渡すスキーマだけ全項目必須に。結果は空欄率0%。

試すなら: Pydantic モデルに上の上書きを足し、model_json_schema() の required が全項目になったことを確認してから Ollama の format に渡す。空欄が「省略」でなく [] で返るかを見る。リスト要素がオブジェクトなら入れ子のモデルにも同じ上書きを。

出典: Qiita — LLMの構造化出力で「後ろの欄だけ空になる」― 原因はrequiredを全指定していないJSON schemaだった
