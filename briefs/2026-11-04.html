Claude Code の 22 課題で 3 モデル×5 エフォートを総当たり: 仕様が固まった実装は Haiku medium で 100%・$0.10、Opus max も 100% だが $5.07・856 秒。差が出たのは上流で、1.3 万行への機能追加の仕様書は Sonnet high 96%・Opus medium 91%・Haiku medium 83%。max は xhigh より時間 2.5〜2.9 倍・費用 1.9〜2.5 倍で満点率はむしろ下がった（OKZAQ 氏 11/3、2.1.308・Max 5x）

— 「全部 Opus で max」は時間と費用だけ増える。工程ごとに --model と --effort を変える根拠になる数字。

OKZAQ 氏（11/3）。自作の 22 課題（実装 9・不明点の洗い出し 3・資料読解 4・文書 2・4 工程 4）を Haiku／Sonnet／Opus 5.5×low〜max で解かせ、費用は API 換算額。実装 9 題は medium 以上なら全モデル満点で、Haiku medium $0.10・159 秒、Opus high $1.18・181 秒、Opus max $5.07・856 秒。満点だった回の割合は max より xhigh が高く（Sonnet 87% 対 74%、Opus 83% 対 65%）、max は時間 2.5〜2.9 倍・費用 1.9〜2.5 倍。

約 1.3 万行への機能追加では仕様書の精度が Sonnet high 96%・Opus medium 91%・Haiku medium 83% と上流で差が出て、仕様が固まった後の実装は全設定が隠しテスト 152 件に合格。結論は、計画と洗い出しは Sonnet high か Opus high、仕様書・試験仕様は Sonnet high か Opus medium、実装は Haiku medium 以上。回数は 1〜3 回で Sonnet と Opus の差はぶれの範囲、採点役は Opus 5.5 high と著者自身が注記。

試すなら: 工程ごとに起動を分け、計画と仕様書は記事のとおり claude -p --model claude-sonnet-5-5 --effort high --output-format stream-json --no-session-persistence、実装は --model を Haiku に・--effort medium に変える（公式 cli-reference 11/4 確認: --effort は low／medium／high／xhigh／max で「使える水準はモデルによる」、--model はエイリアス sonnet／haiku も可だが著者は CLI の版で指す先が変わるのを避けて ID 指定）→ v2.1.317（11/3）から別モデルのサブエージェントは親のエフォートでなくそのモデルの保存済みエフォート（無ければ既定）を使うので、Haiku に実装させるサブエージェントは frontmatter に effort: medium を書いて固定する。

PreToolUse フックで操作を止めるのは終了コード 2 だけ: exit 1・exit 3・例外は 3 回とも素通り、"onFailure": "block" を付けると 4 種の失敗すべてで 0/3（AI Jarvis 氏 11/3、11 条件×3 回）。別件で IT アライグマ氏（11/3）は、判定スクリプトの「該当なし」と「落ちた」が同じ exit 1 で || exit 0 が通していた穴と、matcher が旧ツール名のままで新しい書き込みツールに効かなかった穴を発見

— 11/3 の tamao 氏のフックも exit 2 前提。「止まるはず」の検査が落ちたとき通す設計になっていないか、一度わざと壊して確かめる。

AI Jarvis 氏（11/3）。PreToolUse の終わり方 11 条件×3 回で、Bash が走ったのは exit 0・1・3・例外で 3/3、exit 2 だけ 0/3。"onFailure": "block" を足すと exit 1・例外・ファイル名違いも 0/3。公式 hooks docs も「2 以外や起動失敗は non-blocking」で、onFailure は v2.1.295 から。IT アライグマ氏の直しは「exit 0 かつ出力 none のときだけ通す」「matcher は全ツール」で、判定の答えを終了コードに載せない。

試すなら: 止める hook は sys.exit(2)＋理由を stderr に出し、設定に "onFailure": "block" を足す → 判定スクリプトの先頭に raise ImportError を入れた状態で該当コマンドを頼み、止まることを見てから戻す → v2.1.317（11/3）で Agent SDK のコールバック hook にも onFailure: "block" が入った。

出典: Zenn — exit 1でClaude Codeフックは止まるか33回試した／Zenn — 「該当なし」と「判定器が落ちた」が同じ終了コード1だった
