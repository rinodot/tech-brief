「必ず二重チェック」のような古い念押しを剥がすと、安くて正確になる — Anthropic の実測で費用14.6%減・精度5.3%増。/claude-api prompt-audit は自分の CLAUDE.md にも掛けられる

— 9/13 に週次上限が素に戻る。トークンを減らす手が3つ、数字つきで揃った。

Anthropic の Lance Martin 氏が9/8に公開。「費用と性能はトレードオフではない」として直し方を3つ示した。①キャッシュ命中率を上げる ②上位モデルへ移るときプロンプトの「アンチパターン」を消す ③effort をタスクに合わせる。②の実測は、きれいなプロンプトに「二重に確認せよ」「最大限に徹底的に」「6段階の必須手順」「矛盾する返金ルール」など6種を1つずつ植え、Opus 4.8→Opus 5 でモデルIDだけ変えた場合と /claude-api prompt-audit を掛けた場合を比較。監査後は平均で費用14.6%減・精度5.3%増。

③は SWE-bench Verified で effort を medium にし出力を数文に絞ると、ステップ中央値29→17、費用約55%減。①は tau2-bench retail でキャッシュの区切りを明示し約73%減、合格率は横ばい。含意: 古いモデル向けの念押しは新しいモデルでは費用と精度の両方を削る。prompt-audit は CLAUDE.md や skills も対象なので自分の設定にそのまま使える。

試すなら: Claude Code で /claude-api prompt-audit（同梱スキルなので導入不要）。file:line つきの報告と差分案が出るだけで勝手に書き換えないので、CLAUDE.md の「必ず」「絶対」「二重に確認」の行から見直す。effort は /effort medium で1日試し、ステップ数を比べる。

出典: Claude Blog — Reducing cost and improving performance with Claude Platform

Claude Code に effort の天井 maxEffortLevel が入った — 週次上限の中で「どこまで考えさせるか」を設定ファイルで固定できる

— 1件目の「effort を落とす」を、その場の判断でなく仕組みで効かせる手段。

v2.1.267（9/9）。maxEffortLevel を settings.json に置くと、/effort や --effort で上を指定しても上限で頭打ちになる。「どのスコープからでも低い方が採用」なので、個人設定に置けば自分への歯止めになる。--system-prompt-snapshot off はシステムプロンプトを毎回描き直す指定で、--append-system-prompt の文面を試すときに再起動が要らない。含意: effort は「その場で下げる」より「上限を決める」方が守れる。

試すなら: ~/.claude/settings.json に "maxEffortLevel": "medium" を足して1日回し、/usage の消費と体感を比べる。上げたい日は設定側を直す（上限が勝つ）。

出典: GitHub — anthropics/claude-code v2.1.267

PRレビュー8観点のうち軽い4つを Ollama に回して Claude のトークンを約4割減 — Ollama が止まっていればその回だけ Claude に戻る

— 手元の GPU を「Claude の枠を延ばす側」に使う実例。

GMOペパボのあたに氏が9/8に公開。code／security／test／spec の重い4観点は Claude、DDD／可読性／ログ／性能の4観点は Ollama の qwen3.6:27b へ。切替は MULTI_REVIEW_OLLAMA=1、Ollama が止まっていればその回だけ Claude に戻る。Claude 側のトークン消費は約40%減。ローカル分は自作の ollama-usage で JSON 記録。記録例は入力15,253トークンで404.5秒。含意: 観点を「品質が要る／要らない」で分けるのが先。

試すなら: レビュー観点を2群に分け、軽い群だけ Ollama の /api/chat に投げる。応答の prompt_eval_count／eval_count／total_duration を JSON で残し、Claude 側の ccusage と並べて月次で比べる。

出典: Zenn — Claudeのrate limitをOllama併用でかわし、コストは自作コマンドで見えるようにした
