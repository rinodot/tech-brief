並列で走らせた Claude Code は何回ぶつかっていたか: 2 週間分のログ（7.0GB・シェルコマンド約 10 万件）を hook に再生すると、同時最大 13 セッションで「止めるべきだった」コマンドが 507 件、うち 25 件は別セッションが編集中のツリーでの git add -A コミット。判定は 1 回約 50ms（dooly6276 氏、11/9）

— 並列セッションの事故は起きてから気づく。過去ログに再生して数えられるなら、守りを入れる前に「自分の環境で何件起きていたか」が分かる。

dooly6276 氏（11/9）。自作プラグイン claude-bulkhead の /bulkhead:scan は、~/.claude/projects に残る過去セッションのシェルコマンドを 7 つのガードに通し、当時止められていたはずの件数を数える（外部送信なし）。著者の Mac の 2 週間分（7.0GB・約 10 万件）は 39 秒で読め、同時に動いていたセッションは最大 13 本、止められていたはずのコマンドは 507 件、うち 25 件は別セッションが編集中のツリーでの git add -A コミットだった。

ガードは PreToolUse hook で動く Node スクリプト 7 本。kill-guard は他 worktree のサーバーまで巻き込む pkill node、port-guard は使用中ポートへの二重起動、checkout-guard は他セッション作業中のツリーでの git checkout／git add -A を止め、orphan-reaper は終わったセッションの残留プロセスを数秒で片づける。常駐なし、1 回の判定は約 50ms。含意: 文字列を読む判定でサンドボックスではないが、並列運用の衝突は「数えてから守る」ができる。

試すなら: /plugin marketplace add dooly6276/claude-bulkhead → /plugin install bulkhead@bulkhead → /bulkhead:scan 30d で過去 30 日分をガードに再生し、どのガードが何件鳴ったかを見る（Node 18 以上。リポジトリの hooks.json は PreToolUse の matcher Bash|PowerShell に 7 本、SessionStart に orphan-reaper。ポートとメモリの状態はログに残らないので scan では再生されない）。

公式 Playbook「どの Claude モデルで作るか」: まず Opus 5.5 の effort medium で始め、足りなければ ①自己検証（テスト・ビルド）を足す ②effort を 1 段上げる ③上のモデルへ低い effort から、の順。SWE-bench Pro の部分集合では Opus 5.5 を low で回して失敗分だけ high で再実行すると約 97% を 1 タスク約 $0.17 で通し、全部 high の 95.3%・$0.29 を上回った（Addy Osmani、claude.dev 11/9）

— 週の枠が尽きる人ほど「上げる前に検証を足す」「失敗分だけ上げる」の順番が効く。サブエージェントの model: haiku と /compact してからの切替も公式の勧め。

Addy Osmani（claude.dev、11/9）。価格（入／出 $ per MTok）は Sonnet 5.5 2／10、Opus 5.5 4／20、Fable 5.2 8／40。Claude Code では、ログ読みなど間違いが安く見つかる仕事をサブエージェントの model: haiku に回し（既定は CLAUDE_CODE_SUBAGENT_MODEL）、モデルを切り替える前に /compact する（キャッシュはモデルごと）。含意: 同じタスクを /model で 2 モデルに回し /usage で比べる。

試すなら: .claude/agents/log-reader.md の frontmatter に tools: Read, Grep, Glob, Bash と model: haiku、本文に「Don't edit any files.」と書く → 普段は Opus 5.5・/effort medium で回し、失敗したタスクだけ /effort high で再実行 → モデルを変える前に /compact、同じタスクを 2 モデルで回して /usage を比べる（いずれも Playbook 原文の手順。/effort status で現在の水準を確認）。
