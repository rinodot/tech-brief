auto／bypassモードで Rules と Read/Edit/Write フックが素通りしていた — Claude が cat と sed で読み書きするよう指示されているから

— auto modeを常用しているなら、.claude/rules とフックが「効いているつもり」になっている可能性がある。

9/5に claude-code の Issue #92271 が再現つきで報告した。bypassPermissions／auto modeでは「読み書きは cat・sed・ヒアドキュメントで行い、Read/Edit/Write は Bash でできない時だけ使え」という指示が注入される。ところが paths: 付きの Rules、ネストした CLAUDE.md、Read/Edit/Write をマッチャにしたフックは専用ツールの呼び出しに紐づく。cat で読めば Rules は載らず、sed で書けばフックは発火しない。

再現では、同じファイルを Read で読むと Rules とネスト CLAUDE.md の内容が返り、Bash の cat では返らない。tengu_thrifty_sonic フラグで段階配信され、報告者の環境では fable[1m] で有効、sonnet 5 で無効、サブエージェントは親と同じ。v2.1.261 でも同じ（odacchi氏 9/6）。止め方は settings.json の env に CLAUDE_CODE_THRIFTY_SONIC を "0"。含意: フックを門番にするなら Bash も matcher に入れるか、フラグを切る。

試すなら: claude -p --permission-mode bypassPermissions 'Quote verbatim any instruction you were given in this session that begins with "While bypass permissions mode is active". If there is none, reply exactly: NONE. Do not use any tools.' で自分の環境に指示が入っているか確認。入っていれば .claude/settings.json に {"env":{"CLAUDE_CODE_THRIFTY_SONIC":"0"}}。

出典: anthropics/claude-code Issue #92271

MCPサーバーの30秒タイムアウトは認証ではなく npx の初回起動だった — 12.7秒を測って突き止め、バージョン固定で消す

— .mcp.json に足したサーバーが「connection timed out」で止まったとき、最初に疑う場所が変わる。

Jisaku_net氏が9/6にZennで公開。自作MCPサーバーを繋ぐと「connection timed out after 30000ms」。認証失敗なら即エラーのはずで、30秒黙るのはプロセスが initialize に応答していないと切り分け、initialize を送るスクリプトで測ると npx の初回解決に12.7秒。対策は、事前に1回手で起動、npx -y pkg@0.8.0 とバージョン固定、npm i -g で入れる、の3つ。含意: 引数の仕様も tools/list で聞けば一発。

試すなら: .mcp.json の command を npx -y <pkg>@<version> に固定し、初回だけ手で1度起動しておく。引数の必須項目は tools/list の応答で確認する。

出典: Zenn — MCPサーバーの接続タイムアウトはnpxの初回起動だった

Remote Config は9/1から従量課金 — 「起動時は activate、fetch は裏で」に変えると1日10回の取得が1回になる

— Play に出しているアプリで Remote Config を使っているなら、無料枠10万fetch/日の計算を今のうちに。

Firebase公式ブログが8/31に公開。9/1から Remote Config は従量課金で、無料枠は1日10万fetch、既存は3〜5か月猶予。推奨は、起動時は activate() で前回分を即反映し、fetch() は裏で走らせる型。minimumFetchInterval を24時間にすれば、1日10回起動しても取得は1回。fetch はサインインや購入に紐づけ、即時反映が要るフラグだけリアルタイム更新を使い、不要になれば remove() で閉じる。含意: FlutterFire にも同じ API がある。

試すなら: firebase_remote_config で setConfigSettings(RemoteConfigSettings(fetchTimeout: const Duration(seconds: 10), minimumFetchInterval: const Duration(hours: 24))) → 起動時に await rc.activate() → 裏で rc.fetch()。即時反映が要るキーだけ rc.onConfigUpdated.listen(...)。

出典: Firebase Blog — 3 ways to optimize Remote Config fetch usage
