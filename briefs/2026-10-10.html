EmbeddingGemma 2（10/6）を日本語で使うなら — テキスト検索の精度は旧版と横ばい（8 タスク平均 80.9→80.8）で bge-m3 とも同等、乗り換える理由は薄い。実利は 256 次元に切って保存を 1/3 にすること（1 位は変わらない）と、写真や音声を同じ索引に入れられること（写真 R@1 77.0% vs SigLIP2 37.8%、22 分の音声を約 4 秒）。NVIDIA でも sentence-transformers 6.1＋CUDA で動き、GPU メモリは最大 2.2GB

— 9/21 既報の RAG 実測と 10/2 既報の埋め込み選定（hit@1 25.9%→58.9%）の続き。手元の日本語メモの RAG で埋め込みを替えるかを、公式ガイドと日本語の実測 4 本で決める。

Google の公式ガイド（10/6）。テキスト・コード・画像・動画・音声を 768 次元の 1 つの空間に埋め込み、テキストだけなら 270M、全部で 740M。256 次元に切ってもテキスト・コードの品質はほぼ維持、128 次元で約 90%。100 万本の保存は 768 次元で約 1.5GB、128 次元で約 250MB。文脈 8,192、Apache 2.0。

日本語の実測。takuh 氏（10/7、Mac）は日本語テキスト検索 8 タスク平均が旧版 80.9→80.8 で「乗り換える理由は見当たらない」、写真検索は R@1 77.0%（SigLIP2-base 37.8%）。serotoninmax 氏（10/8、146 件×91 問）は意味検索 top10 が EG2 0.28／0.35、bge-m3 0.28／0.38 で同等。nakanishitf 氏（10/7、Colab T4）は 256 次元でも 1 位が同じ。matu79go 氏（10/9）は NVIDIA GB10＋CUDA 13 で GPU メモリ最大 2.2GB。含意: 日本語テキストだけなら今のまま。替える理由は 256 次元で保存 1/3 と、写真・音声を同じ索引に入れられること。

試すなら: pip install -U "sentence-transformers[image,audio,video]" transformers（sentence-transformers 6.1.0 以降）→ m = SentenceTransformer("google/embeddinggemma-2", truncate_dim=256, config_kwargs={"vision_config": None, "audio_config": None}) でテキストだけ読む → 文書は m.encode(docs, prompt_name="Document")、質問は prompt_name="SearchQuery" → 手元の日本語メモで 10/2 の要領（質問 20〜30 本の hit@1）を今の埋め込みと比べ、差がなければ据え置く（コードは公式ガイド。Ollama は ollama pull embeddinggemma-2:270m（378MB、テキストのみ）。v0.40.0 の release notes は MLX 対応のみ記載）。

Claude Code の Routines は URL への POST でも起動できる（API トリガー。Pro／Max も可）— Terass の homu_konamilk 氏（10/9）は Notion／Slack の依頼を受付サーバー経由で各自の Routine の fire URL に流し、プロンプトは「main を取り直して repo の instructions/ を読む」だけの短い起動文に。1 か月の依頼分は API 換算で約 $1,400、支払いは Team のプレミアムシート月 $110

— この朝刊もクラウドセッションの連鎖で動いている。9/29 既報の routines に「外から叩く」入口があれば、Crashlytics の通知や CI の失敗から調査セッションを起こせる。

公式 docs では Routine にスケジュール・GitHub イベント・API の 3 種を重ねられ、API は /fire に Bearer トークンで POST するとセッションが起動する。text の本文は信頼しないデータとして包まれ、プロンプトに「payload を調べよ」と書かないと無視される（1 ルーティン 30 回／時）。homu 氏の型は、プロンプトを短い起動文にして手順は repo の instructions/ に置くこと。規則の変更は main へのマージで済む。research preview。

試すなら: claude.ai/code/routines で Routine を Edit → Add another trigger → API → Generate token（表示は 1 回だけ）→ curl -X POST https://api.anthropic.com/v1/claude_code/routines/<ID>/fire -H "Authorization: Bearer <TOKEN>" -H "anthropic-beta: experimental-cc-routine-2026-04-01" -H "anthropic-version: 2023-06-01" -H "Content-Type: application/json" -d '{"text":"Crashlytics の新規クラッシュを調べて修正 PR の案を作る"}' → プロンプトに「routine-fire-payload の内容を調査対象にする」と明記し、手順書は repo の docs/ に置いて「main を fetch してから読む」の 1 行にする（手順と上限は code.claude.com/docs/en/routines。API 起動はアカウントで 100 回／時）。

Flutter アプリの中でローカル LLM を動かす Dart パッケージ llamadart 0.11 — GGUF を llama.cpp で読み、LlamaEngine.load と ChatSession.send の数行で会話。Android・iOS・macOS・Windows・Linux・web 対応、GPU は Linux／Windows が Vulkan、Android は実験的。LiteRT-LM と画像生成（プレビュー）も同じ API。Google Developer Expert の Jhin Lee 氏が 10/8 に解説

— 9/6 既報の num_gpu や 10/4 既報の VRAM の式は PC の話。アプリ側で小さなモデルをオフラインで動かす入口が Dart だけで用意できる。

Jhin Lee 氏（leehack、10/8）。LlamaEngine.load にモデルと ModelParams を渡して読み、ChatSession に send() すると古いターンは文脈に収まるよう自動で切り詰められ、system prompt は残る。要件は Dart 3.10.7／Flutter 3.38 以上。tok/s やメモリの実測は記事にない。含意: 端末内の要約・分類なら Firebase AI Logic を経由せずオフラインで試せる。pub.dev は 0.11.1、MIT。

試すなら: flutter pub add llamadart（iOS／macOS は llamadart_llama_cpp_flutter も）→ 上の LlamaEngine.load と ChatSession を書き、まず PC（Windows なら Vulkan）で SmolLM2-135M-Instruct-Q2_K.gguf を読ませて動作を見る → Android 実機は gpuLayers: 0 の CPU から始め、応答時間とメモリを flutter run --profile の DevTools で測る（API は pub.dev/packages/llamadart の README。Android の Vulkan は実験的・opt-in）。
