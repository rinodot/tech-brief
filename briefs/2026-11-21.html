欲しい小物を言葉で頼むと、Claude が 3D CAD を動かして、刷れる形まで作る

オープンソースの 3D CAD「SolidCraft」は、MCP で AI に操作させられる。ブラウザ版を Claude Code（Opus 5.5）に操作させたら、スマホスタンドが約 7.6 分・8 回の実行でできた。1 回目で形になり、残りは角の丸めで詰まって直した

いま
1形は頭にあるのに、3D CAD の操作を覚えるのが壁になるSolidCraft のコマンドは 819 個（今夜ブラウザ版で数えた）
2測って描いて押し出し、合わなければ最初から
SolidCraft を Claude につなぐと
3言葉で頼むと、Claude が CAD のコマンドを 1 つずつ打って形にするClaude Code には claude mcp add solidcraft -- solidcraft-cli mcp の 1 行。開いているアプリにつなげば、作るところを横で見られる（README）
4毎回、出来上がりの絵と寸法の数字を見て、自分で直す今夜の試しでも、止まった手順はエラー文を読み、コマンドの説明を引き直して通した

  • やり方: ブラウザ版（app.solidcraft.io・v0.45.0）を headless Chrome で開き、ページの操作口 window.solidcraft にコマンド列を流して、寸法と等角図を返す小さな道具を作った。それだけを claude -p（Opus 5.5）に渡して頼んだ。新しく入れたものは無い（Chrome の設定も一時フォルダ）
  • 止まったのは 4 回（2・3・4・7 回目）。Claude の報告では、立体を一度にまとめて丸めると角の計算で失敗したので、断面の段階で丸めてから押し出し、つながった円弧は外して直線の辺だけを丸める指定に変えて通した

まだ試していない公開されたモデルを元と比べて数え直した入れる手間 1 時間ほど（一時フォルダに MLX）対象: 手元の小さな LLM

小さなローカル LLM の困った癖を、Claude が重みを直接書き換えて直す。学習はしない

MIT CSAIL の Weight-Space Programming（11/2）。0.8B のモデルの「考えすぎて終わらない」癖を、別の LLM が重みの 0.016% を書き換えて直した。公開された書き換え後のモデルを元と比べると、変わっていたのは本当に 2 枚の行列だけだった

いま
1小さなモデルは、考えるうちにぐるぐる回って、上限まで止まらないQwen3.5-0.8B（思考オン）は、MATH-500 の答えの 93% がトークンの上限（32,768）に達した（ブログ）
2癖を直すには、データを集めて学習し直すのがふつう紹介した Zenn の記事:「モデルの振る舞いを変える方法は、これまで主にプロンプトかファインチューニングでした」
Weight-Space Programming では
3Claude が、モデルを動かしては中の数字を読み、ぐるぐるの元を探す見つかったのは層 15 と 19 の MLP が書き込む 1 つの「向き」。使えたのは練習問題と 50 回の試し（ブログの実験 8。編集役は GPT-6 Astra）
4その向きを、2 枚の行列の 64 列ずつから引くだけ。勾配も学習も使わない変えた重みは 131,072 個、全体の 0.016%（ブログ）

数字: 同じ設定（思考オン）で、書き換える前と後

重みの 0.016%50 回の試しで
  • 数字はブログの表。Hugging Face のモデルの説明書にある再実行（500 問 × 4 回）では 51.0%、上限に達したのは 31.6%（モデルの説明書）
  • 伸びた中身は「ループという故障を取り除いた」こと。ブログ自身が「隠れていた力を出す邪魔は除けたが、無い力は足せなかった」と書く（下の「気をつけること」）

手元で確かめた: 公開された書き換え後のモデルを、元のモデルと行列ごとに比べた

1書き換わっていたのは層 15 と 19 だけ。間の層 17 は 1 個も違わないどちらも違いは 64 列に収まり、ほぼすべての行にかかっていた（層 15 は 1,024 行、層 19 は 1,023 行）
2重み全体（約 1.6GB）は落とさず、比べたい行列だけを取り寄せて数えたファイルの見出しから場所を読み、HTTP の範囲指定で 1 枚 7MB ずつ。新しく入れたものは無い（Python の標準の道具だけ）
  • 比べたのは Qwen/Qwen3.5-0.8B（説明書が名指しする版）と RikiyaT/Qwen3.5-0.8B-weight-space-programming の layers.{15,17,19}.mlp.down_proj.weight。違う数字の合計 130,188 個は、ブログの 131,072 個（64 列 × 1,024 行 × 2 枚）より 884 個少ない。足し引きのあとも同じ数字に丸まった分と見ているが、確かめていない
  • 言語の部分のほかの 317 枚（全体は 488 枚）が同じかは、全体を落としていないので確かめていない（説明書は「違うのはこの 2 枚だけ」と書く）

日本語でも: Claude に、何を聞いても Markdown で答える癖を消させた例（河内氏、11/17）

1朝ごはんのおすすめを聞いても、見出し・太字・箇条書き
2「使わないで」と頼んでも、半分は残る
3重みを書き換えると、ほぼふつうの文章に吹き出しの文は絵のための例で、記事の答えそのものではない
  • 編集役は Claude。指示書で禁じたのは、勾配計算・学習、システムプロンプトや生成の設定で解決すること、評価用の問題を開くこと、インターネット。開発用の評価は 15 回まで（記事）
  • 編集役の Claude は約 45 分・評価 13 回で、「中立」と「Markdown 禁止」の 2 つの指示で同じ答えを読ませたときの差を、層 13〜22 の 10 層に足した。層 14 だけでは効かなかった（記事）
  • Claude が見ていない評価用 30 問でも 100% → 3%（1 問）。計算と一般常識の 20 問は 11 問正解のまま変わらず（記事。MLX と mlx-lm 0.32.2）

気をつけること

無い力は足せないループしない Gemma 3 270M では、どの編集も MATH-500 を 1 点ほどしか動かせなかった（ブログ）
思考を切るだけで 44.2%再実験の指摘。著者は「思考を切れば点は上がるが、重みが直ったわけではない」と 11/12 に反論
ほかの所も変わるMarkdown の例では具体的な箇条書きが消え、「まずに」という不自然な語が 30 問中 8 問に出た（記事）

始めるなら

1一時フォルダに uv venv を作り、mlx-lm==0.32.2 と Qwen3.5-0.8B を入れる（グローバルには入れない）
2直したい癖を 1 つ決め、Claude Code に指示書を渡す（学習・システムプロンプト禁止、評価は 15 回まで）
3Claude に見せない問いで、前と後、ほかの所への影響を比べる
▶ これを始める一時フォルダで、Qwen3.5-0.8B の英語混じりか Markdown の癖を Claude に重みで直させる。WorkIQ で Orca に新しいセッション
送ると確認画面が開き、▶ を押すと Mac の Orca でセッションが始まる

2自分のスマホで試すにも、ケーブルか署名の鍵か、開発者アカウントが要った発表の言い方:「これまでは USB デバッグのケーブル、手元の署名の鍵、開発者コンソールのアカウントが要った」
AI Studio の Android 版では

気をつけること
