Flutter の dart:io HttpClient は OS のネットワーク設定を通らない: 端末の proxy 設定は読まず（環境変数 http_proxy だけ）、Android では証明書検証も内蔵 BoringSSL で OS の失効リストを見ない。侵害された eMudhra 中間 CA を塞ぐ修正は Dart 3.13.7／Flutter 3.47.8（GHSA-frr6-h895-5pxp、10/23、High）で、アプリの再ビルドと再配布が要る。OS の経路を使うなら cronet_http／cupertino_http（koji_1009 氏 10/26）

— Play で配っている Flutter アプリの Android 版は、3.47.8 で作り直して出し直すまで OS 側の証明書失効が効かない。読者の公開アプリに直接かかる。

koji_1009 氏（10/26）。dart:io は TLS まで SDK 内の自前実装で、OS の proxy 設定を読まず、Android では証明書も内蔵 BoringSSL で検証して OS の失効リストを見ない。公式勧告（10/23、High）: eMudhra の中間 CA 8 枚が侵害、Android・Windows・Linux が対象（Web・iOS・macOS は対象外）。修正は Dart 3.13.7／Flutter 3.47.8。ブロックリストはアプリ側に入るので再ビルド・再配布が要る。

試すなら: flutter upgrade → flutter --version で 3.47.8 以上（Dart 3.13.7 以上）を確認 → Android 版をビルドし直して Play に出し直す（勧告の対処は「上げて再ビルド・再配布」のみ、回避策なし）→ OS の proxy・証明書・更新を活かしたい通信は http の Client を Android で CronetClient.fromCronetEngine(CronetEngine.build(), closeEngine: true)、iOS／macOS で cupertino_http に切り替える（dio なら Dio()..httpClientAdapter = NativeAdapter()。例外型が SocketException から ClientException 系に変わる、Image.network は dart:io のまま、Windows は非対応）→ badCertificateCallback で true を返す実装は全証明書を通すので使わない。

出典: Zenn — dart:ioと端末のネットワーク設定
